# 测试大纲生成器

按中国招投标与验收规范，把「要测什么」变成可执行的测试大纲。每个测试项都有可量化的判定准则——这是它和网上模板最大的区别。

## 一分钟演示

**输入**

```
项目：某单位采购下一代防火墙 2 台、IDS 1 台
依据：招标文件第三章、GB/T 22239-2019
用途：投标技术方案附件
```

**输出（节选）**

| 编号 | 测试项 | 判定准则 | 优先级 |
|---|---|---|---|
| TC-PERF-01 | 整机吞吐量 | 1518B 包长、RFC2544 双向、60s，吞吐 ≥ 10Gbps 且丢包 ≤ 0.001% | P0 |
| TC-FUNC-05 | 策略冲突优先级 | 同一流量命中「允许」「拒绝」两条策略时按优先级执行，命中计数正确 | P0 |
| TC-REL-02 | 双机热备切换 | 断开主链路，切换 ≤ 3s，会话中断 ≤ 5s | P1 |

配套输出：测试环境清单、缺陷分级表、记录表模板、执行计划。

## 它解决什么

| 痛点 | 现在 |
|---|---|
| 网上模板只有测试项，没有判定准则 | 每项强制写「通过/不通过」的量化标准 |
| 步骤写成「检查功能是否正常」，换个人就跑不起来 | 六要素：前置/步骤/预期/判定/记录/异常 |
| 性能测试没有测试条件，数字没法比 | 包长、时长、并发、工具、口径全部写明 |
| 兼容性漏掉国产化环境 | 默认覆盖麒麟/统信、达梦、国产浏览器 |
| 验收时没有记录表，签字没依据 | 附录直接给可打印模板 |

## 怎么用

1. 说清被测对象和项目类型（采购/集成/软件交付）
2. 给依据：招标条款、国标号、合同验收条款
3. 说用途：投标附件 / 交付验收 / 内部自测

## 输出物

- 大纲正文八章骨架
- 测试项矩阵（五类 × N 项，带优先级和依据条款映射）
- 六要素用例（可直接执行）
- 缺陷分级与通过标准
- 记录表、环境检查清单

## 适用与不适用

**适用**：安全设备采购、系统集成、软件交付、等保测评前自测、工程验收。

**不适用**：替代第三方检测报告、实施渗透测试、性能调优、编造测试记录。

## 依据说明

- 通用框架参考 GB/T 25000.51（软件质量）与 GB/T 22239-2019（等级保护）的测试思路
- 具体判定阈值**以招标文件和合同条款为准**，本技能给的数值是行业常见区间，不构成标准原文
- 不联网、不调用外部工具
