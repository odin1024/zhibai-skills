# 常见问题

## 1. 只有招标文件，没有评分办法，能用吗？

能，但要降级。没有评分办法就无法做「评分点覆盖」，只能按通用骨架写。这时技能会在首页醒目标注：**本版未针对任何评分表，正式投标前必须按评分办法重排**。请尽量先找到评分办法，它通常在「评标办法」「评分细则」「评审因素」章节，有时在附件里。

## 2. 评分办法里一项 15 分、没细分每项多少分，怎么拆？

拆成采分点，但**分值列写「15 分（含 N 项，未细分）」**，不要自行平均分配成每项 3 分。自行分配等于伪造招标信息，也可能让章节权重判断出错。

## 3. 能不能直接帮我编一个检测报告编号 / 业绩数量？

不能。资质、业绩、型号、检测数据、案例、人员姓名属于可核验事实，一律【待确认】并列入待补清单。标书上的每个数字都可能被要求举证，编一个看起来合理的数字是最大的风险源。

## 4. 技术方案里能不能写「完全满足招标要求」？

不建议。除非招标文件明确要求这种表述，且参数响应表里确实没有任何「负偏离 / 待确认」。更稳妥的写法是「逐条响应情况见参数响应表；待确认项已列入待补清单」。

## 5. 和参数响应表、测试大纲的关系是什么？

- 参数响应表：回答「每条参数响应得怎样」；
- 测试大纲：回答「怎么验证」；
- 技术方案：回答「整体怎么做、评委凭什么给分」。

本技能会输出一张**一致性校验表**，比对指标、型号数量、术语、引用、标准版本、偏离状态六类口径。三者不一致是标书被打回的高频原因。

## 6. 标准号（比如 GB/T 22239-2019）可以直接抄进方案吗？

技能会给出常见标准清单，但会同时提示：**引用前必须核对招标文件指定版本与标准的现行有效状态**。招标文件指定了版本就以招标文件为准；只写「符合国家相关标准」时，不要自己编一串标准号充数，改成「按招标文件指定标准及投标时现行有效版本执行，清单见附件【待补】」。

## 7. 扫描件 / 表格很乱，识别不清怎么办？

识别不清的地方标【识别不清：请核对原文第 X 页】，不要猜字。表格可以保留行列结构贴进来；如果行列错位，技能会先请你确认列的含义，再拆表。★ / ▲ 这类符号务必人工复核，它们往往关联实质性条款。

## 8. ★ / ▲ 条款怎么处理？

在「约束表 C」里单列，逐条检查有没有响应。后果**按招标文件原文表述**，不自行推断「一定废标」。技术方案正文里不得把「负偏离 / 待确认」写成「满足」。

## 9. 能不能保证中标 / 保证通过等保测评？

不能，也不会这样写。评标结果、测评结论由评委和具备资质的测评机构判定，属于不可承诺事项。方案里只能写「按测评要求逐项准备并配合复测，结论以测评机构报告为准」。

## 10. 篇幅有要求（比如技术方案不超过 50 页），怎么控制？

在输入里写清页数或字数上限。技能会在章节骨架里给「预计页数」，并按评分项分值分配篇幅；高分项多写，低分项合并。格式要求（是否单独成册、章节编号规则）优先于默认的排序规则。

## 11. 已有一版技术方案，只想查漏项，可以吗？

可以，这是最省时间的用法。贴来评分办法 + 现有方案目录/正文，技能会跑 S1、S2、S6，输出覆盖矩阵、漏项清单和一致性校验结果，不重写全文。

## 12. 适用哪些项目类型？

主要面向网络安全与信息化相关项目：安全设备采购、系统集成与网络建设、等保测评与整改、数据安全、运维与安全运营、软件平台建设。通用货物或服务类项目也能用「评分点倒推 + 五段式」的方法，但行业专属的方案要素需要由用户提供，技能不会假装懂一个没给过资料的行业。
