# 评分标准映射库

> 用途：把招标文件里那句笼统的评分描述，拆成能逐条给分、能倒推章节、能配佐证材料的采分点。
> 使用原则：**一切以招标原文为准**。本库是「常见形态速查」，不是评分模板；招标文件的措辞、分值、格式要求永远优先。

---

## 〇、拆解通则

一个评分项通常长这样：

> 「技术方案完整性 15 分：方案包含需求理解、总体架构、部署实施、运维服务、应急预案，每项 3 分。」

拆成 5 行，每行一个采分点。若原文没细分分值，写「15 分（含 5 项，未细分）」，**不要自行平均分配**。

每个采分点必须填齐五列：`章节 / 论证方式 / 佐证材料 / 可验证指标 / 状态`。
论证方式五选一：流程说明、架构与拓扑、量化指标与验证方法、组织与人员安排、历史材料佐证。

## 一、十类常见评分项速查

### 1. 需求理解 / 项目理解

| 项 | 内容 |
|---|---|
| 典型表述 | 「对项目需求理解深入、重点难点分析到位」 |
| 常拆采分点 | 业务现状复述、关键需求识别、重点难点、针对性措施、与招标条款的对应 |
| 建议章节 | 第 1 章 项目理解（或按招标格式要求） |
| 论证方式 | 流程说明 + 招标条款逐条对应表 |
| 得分策略 | 用表格把「招标条款号 → 我方理解 → 对应方案章节」列全，比写三页抒情文字有效 |
| 常见失分点 | 大段复述招标文件原文；只讲行业通用趋势，不讲本项目；没有对应表 |
| 佐证材料 | 招标文件条款对照表、现场调研记录（如有） |
| 可验证指标 | 一般不设硬指标；可写「招标要求覆盖率 100%（逐条对照）」 |

### 2. 总体架构 / 总体设计

| 项 | 内容 |
|---|---|
| 典型表述 | 「总体架构设计合理、层次清晰、扩展性好」 |
| 常拆采分点 | 总体架构、分层与模块划分、接口与数据流、扩展性/容灾、安全分区 |
| 建议章节 | 第 2 章 总体设计 |
| 论证方式 | 架构与拓扑（必须配拓扑图或结构图） |
| 得分策略 | 一张分层架构图 + 一段「每个组件解决哪个招标条款」的说明；标明边界与接口 |
| 常见失分点 | 只放一张厂商通用产品架构图；图中设备与设备清单不一致；没有说明数据流 |
| 佐证材料 | 拓扑图、产品彩页（型号须与清单一致）、接口说明 |
| 可验证指标 | 组件覆盖率、接口数量与协议、可用率设计值、扩展容量上限（须可验证） |

### 3. 功能响应 / 技术参数满足度

| 项 | 内容 |
|---|---|
| 典型表述 | 「技术参数响应情况」「功能满足度」 |
| 常拆采分点 | 逐条响应、★/▲ 条款、正偏离说明、证明材料索引 |
| 建议章节 | 可单列「技术响应」章，但**正文主体应交给参数响应表**，本技能只做口径对齐 |
| 论证方式 | 量化指标与验证方法 |
| 得分策略 | 引用参数响应表编号，不重复抄一遍参数；把「怎么验证」写进测试大纲 |
| 常见失分点 | 技术方案里写的数值与响应表不一致；把「待确认」写成「满足」 |
| 佐证材料 | 参数响应表、检测报告、产品彩页页码 |
| 可验证指标 | 每个 ★ 条款一条验证方法与判定准则 |

### 4. 实施方案 / 部署组织

| 项 | 内容 |
|---|---|
| 典型表述 | 「实施方案可行、进度安排合理、人员配置充足」 |
| 常拆采分点 | 实施阶段划分、进度计划（含里程碑）、组织架构与职责、人员资质与投入、进场与配合条件、风险与应对 |
| 建议章节 | 第 4 章 实施方案 |
| 论证方式 | 组织与人员安排 + 流程说明 |
| 得分策略 | 甘特表或阶段表 + 角色职责矩阵（RACI 简化版）+ 每个阶段的交付物与验收点 |
| 常见失分点 | 只有一句「按进度计划实施」；人员名单是编的；没有写甲方配合条件 |
| 佐证材料 | 项目组织机构图、人员证书【必须由投标人提供】、类似项目进度记录 |
| 可验证指标 | 里程碑数量与日期、阶段交付物清单、到场人天（以投标承诺为准） |

### 5. 质量保障 / 项目管理

| 项 | 内容 |
|---|---|
| 典型表述 | 「有完善的质量管理体系与过程控制措施」 |
| 常拆采分点 | 质量目标、过程检查点、文档管理、变更控制、问题跟踪与闭环、验收配合 |
| 建议章节 | 第 5 章 质量保证 |
| 论证方式 | 流程说明 + 记录表模板 |
| 得分策略 | 给出可填写的记录表模板（检查单、问题单、变更单），比写「严格把控质量」具体得多 |
| 常见失分点 | 只贴一张体系认证证书，没有本项目怎么用；记录表没有字段 |
| 佐证材料 | 体系证书【待补】、记录表模板、检查点清单 |
| 可验证指标 | 检查点数量、问题闭环时限承诺、文档交付清单 |

### 6. 安全与合规

| 项 | 内容 |
|---|---|
| 典型表述 | 「符合等级保护 / 数据安全要求」「安全设计合理」 |
| 常拆采分点 | 合规依据、安全分区与边界、身份与访问控制、日志与审计、数据安全与备份、应急处置 |
| 建议章节 | 第 3 章或独立「安全设计」章 |
| 论证方式 | 架构与拓扑 + 标准条款对应表 |
| 得分策略 | 把「招标文件要求 → 标准条款 → 方案措施 → 验证方法」列成四列表 |
| 常见失分点 | 标准号写错或版本失效；堆标准名但没有对应措施；把合规写成产品功能清单 |
| 佐证材料 | 标准条款对照表、等保测评报告【待补】、安全产品资质【待补】 |
| 可验证指标 | 对照条款覆盖率、审计日志留存期、备份 RPO/RTO 设计值（须可测） |

### 7. 运维与售后服务

| 项 | 内容 |
|---|---|
| 典型表述 | 「运维服务方案完善、响应及时、有本地化服务能力」 |
| 常拆采分点 | 服务范围与期限、响应时限分级、服务渠道、备件与替换、巡检计划、培训、服务报告 |
| 建议章节 | 第 6 章 运维服务 |
| 论证方式 | 流程说明 + 量化指标与验证方法 |
| 得分策略 | 响应时限分级表（故障等级 / 响应时间 / 到场时间 / 解决时限 / 升级路径）+ 巡检频次表 |
| 常见失分点 | 承诺「7×24 小时响应」却没有分级和判定口径；培训只有一句话；没有服务报告模板 |
| 佐证材料 | 服务网点证明【待补】、备件清单、服务报告模板、培训大纲 |
| 可验证指标 | 响应/到场/解决时限、巡检频次、报告提交周期、可用率承诺 |

### 8. 应急预案 / 业务连续性

| 项 | 内容 |
|---|---|
| 典型表述 | 「应急预案完备，含演练计划」 |
| 常拆采分点 | 风险场景清单、应急组织与联系人、分级响应流程、恢复步骤、演练频次与记录、复盘改进 |
| 建议章节 | 第 7 章 应急预案 |
| 论证方式 | 流程说明 + 记录表模板 |
| 得分策略 | 至少列 3 个具体场景（设备故障、链路中断、数据误删/勒索），每个给触发条件与恢复步骤 |
| 常见失分点 | 只写「启动应急预案」；没有演练频次；没有记录表；联系人是编的 |
| 佐证材料 | 演练记录模板、应急联系人表【待补】、历史演练记录【待补】 |
| 可验证指标 | 场景数量、演练频次、RTO/RPO 设计值、记录表字段完整度 |

### 9. 验收与测试

| 项 | 内容 |
|---|---|
| 典型表述 | 「验收方案清晰、测试项完整」 |
| 常拆采分点 | 验收阶段划分、测试项矩阵、六要素用例、判定准则、缺陷分级、记录表 |
| 建议章节 | 可单列「验收方案」，但**主体应交给测试大纲**，本技能只引用并保持口径一致 |
| 论证方式 | 量化指标与验证方法 |
| 得分策略 | 引用测试大纲的测试项编号，方案里只写「验证方式与判定准则摘要」 |
| 常见失分点 | 方案里写 10 Gbps、测试大纲测 5 Gbps；判定准则写「满足要求」这种无法判定的话 |
| 佐证材料 | 测试大纲、记录表模板、测试用例编号 |
| 可验证指标 | 每个指标 = 指标值 + 验证方法 + 判定准则 + 验证阶段 |

### 10. 培训 / 移交 / 文档

| 项 | 内容 |
|---|---|
| 典型表述 | 「培训计划合理、交付文档齐全」 |
| 常拆采分点 | 培训对象与分层、课程内容与课时、培训方式、考核、文档清单与移交流程 |
| 建议章节 | 第 8 章 培训与移交 |
| 论证方式 | 组织与人员安排 + 清单 |
| 得分策略 | 课程表（对象 / 内容 / 课时 / 方式 / 考核）+ 文档交付清单表（名称 / 份数 / 格式 / 时间） |
| 常见失分点 | 只写「提供培训」；文档清单没有格式和交付时间 |
| 佐证材料 | 课程大纲、教材目录、文档清单模板 |
| 可验证指标 | 课时数、培训场次、签到与考核记录、文档交付项数 |

## 二、从采分点到章节的倒推示例

评分办法（节选）：

| 评分项 | 分值 | 原文采分点 |
|---|---:|---|
| 技术方案 | 30 | 需求理解、总体架构、部署实施、应急预案（未细分） |
| 运维服务 | 10 | 响应时限、巡检计划（各 5 分） |
| 验收方案 | 10 | 测试项完整性、判定准则（各 5 分） |

倒推骨架：

| 章 | 标题 | 对应采分点 | 论证方式 | 需补材料 |
|---|---|---|---|---|
| 1 | 项目理解 | S-01-01 | 条款对照表 | 招标文件条款号 |
| 2 | 总体设计 | S-01-02 | 架构与拓扑 | 拓扑图【待补】 |
| 3 | 安全设计 | S-01-02（合并） | 标准条款四列表 | 标准版本核对 |
| 4 | 实施方案 | S-01-03 | 阶段表 + 职责矩阵 | 人员名单【待补】 |
| 5 | 运维服务 | S-02-01 / S-02-02 | 时限分级表 | 网点证明【待补】 |
| 6 | 验收方案 | S-03-01 / S-03-02 | 引用测试大纲 | 测试大纲 |
| 7 | 应急预案 | S-01-04 | 场景 + 记录表 | 演练记录模板 |

注意：分值未细分的 S-01 系列，矩阵里写「30 分（含 4 项，未细分）」，不自行标成每项 7.5 分。

## 三、常见失分点总表（交付前扫一遍）

| 类别 | 检查句 |
|---|---|
| 覆盖 | 评分办法里每一个采分点，都能在目录里指到具体章节吗？ |
| 对应 | 每章标题里有没有评分项原话里的关键词？ |
| 判据 | 每个量化指标，能在测试大纲里找到对应的验证方法和判定准则吗？ |
| 佐证 | 每个「详见附件」是不是都有编号、名称、页码（或标了待补）？ |
| 事实 | 有没有任何一处数字/型号/证书/人名是用户没提供、我补上去的？ |
| 口径 | 三份材料里的指标、型号、数量、术语、标准版本是否一致？ |
| 实质性 | ★ / ▲ 条款是否逐条响应，且后果按招标原文表述？ |
| 格式 | 章节编号、页数上限、是否单独成册、字体字号等格式要求是否满足？ |
| 措辞 | 有没有「完全满足」「业界领先」「零风险」这类没有判据的话？ |
| 待办 | 待补材料清单是否交到用户手上，并写清找谁要？ |

## 四、不要做的事

- 不把本库的分类当成招标文件的分类往里套。招标文件写「施工组织设计」就用它的词，别改成「实施方案」。
- 不用本库替用户判断「这条会不会废标」。废标后果只按招标文件原文表述，拿不准就提示澄清。
- 不自行给分值、不自行加权、不预测得分。
- 不把「未细分分值」的评分项拆成等值几份写进矩阵，那是伪造招标信息。
