# 安全与 IT 项目方案要素库

> 用途：写「方案内容」和「可验证指标」两段时，快速查到这类项目通常要讲清哪些要素、哪些指标是可验证的、哪些坑最容易踩。
> **这不是可直接复制的方案正文**。每个项目的范围、设备、指标都来自招标文件和投标人真实材料，本库只提供检查维度。

---

## 〇、三条使用铁律

1. **指标三件套**：任何量化指标必须同时写「指标值 + 验证方法 + 验证阶段」，判定准则要能给出「通过 / 不通过」，不能写「满足要求」。
2. **标准先核对**：下表标准号取自全国标准信息公共服务平台公开检索结果与政府采购公告引用，**引用前必须逐条核对招标文件指定版本与标准的现行有效状态**。招标文件指定的版本优先。
3. **事实不补**：设备型号、数量、检测数据、资质编号、人员名单，一律来自投标人提供的材料；没有就写【待确认】并列入待补清单。

## 一、常用标准与依据核对表

| 名称 | 常见编号 | 常用于 | 核对提示 |
|---|---|---|---|
| 信息安全技术 网络安全等级保护基本要求 | GB/T 22239-2019 | 等保建设、安全设计 | 核对招标文件是否指定版本与等级（如第三级） |
| 信息安全技术 网络安全等级保护安全设计技术要求 | GB/T 25070-2019 | 安全架构设计 | 与基本要求配套使用 |
| 信息安全技术 网络安全等级保护测评要求 | GB/T 28448-2019 | 等保测评方案 | 测评项与判定准则的出处 |
| 信息安全技术 网络安全等级保护测评过程指南 | GB/T 28449-2018 | 测评过程与流程 | 测评阶段划分 |
| 信息安全技术 网络安全等级保护定级指南 | GB/T 22240-2020 | 定级备案 | 定级对象与等级判定 |
| 信息安全技术 网络安全等级保护实施指南 | GB/T 25058-2019 | 实施与整改 | 公开资料中对年份表述不一致，务必以官方平台与招标文件为准 |
| 信息安全技术 信息系统密码应用基本要求 | GB/T 39786-2021 | 密评、密码应用方案 | 密评项目常见依据 |
| 计算机信息系统 安全保护等级划分准则 | GB 17859-1999 | 上位标准引用 | 通常作为背景依据，不作为方案措施 |
| 中华人民共和国网络安全法 / 数据安全法 / 个人信息保护法 / 密码法 | — | 合规依据 | 引用法律名称即可，不自行解读条款适用范围 |

**不确定的处理**：若招标文件只写「符合国家相关标准」，方案里写「按招标文件指定标准及投标时现行有效版本执行，具体清单见附件 X【待补：由投标人核定】」，不要自己编一串标准号充数。

## 二、六类项目的方案要素

### 1. 网络安全设备采购（防火墙、IPS、WAF、态势感知、堡垒机等）

| 维度 | 要素 |
|---|---|
| 方案内容 | 部署位置与串/旁路方式、防护对象与区域边界、策略初始配置与变更流程、日志与告警去向、高可用/双机方式、与现有设备的兼容与对接 |
| 架构描述 | 必须画清「流量从哪进、经过哪台设备、日志送到哪、旁路镜像接在哪」；图中设备型号数量与设备清单一致 |
| 可验证指标示例 | 吞吐/并发/新建连接速率（按检测报告取值）、策略生效验证、故障切换时间、日志上报完整率、告警到平台时延 |
| 验证方法写法 | 「按测试大纲 T-xx 用例，以 <工具/方法> 施加 <负载/攻击样本>，记录 <观测项>，判定准则：<可判定的条件>」 |
| 常见坑 | 彩页参数直接抄进正文却没有检测报告页码；旁路设备写成串接；双机切换只写「支持 HA」不给切换判据；忽略与现有网络地址的冲突 |

### 2. 系统集成与网络建设

| 维度 | 要素 |
|---|---|
| 方案内容 | 现状与约束、总体分层、IP/VLAN/路由规划原则、设备与链路清单对应、割接方案与回退、连通性测试、文档与资产移交 |
| 架构描述 | 分层图 + 链路表（链路编号 / 两端设备 / 带宽 / 用途 / 冗余方式） |
| 可验证指标示例 | 链路可用率、割接窗口时长、回退触发条件与耗时、配置项核对通过率、ping/业务连通性测试通过率 |
| 常见坑 | 没有割接回退方案；链路表与设备清单数量对不上；只写「完成调试」不给判定准则；忽略甲方业务停机窗口 |

### 3. 等保测评与整改服务

| 维度 | 要素 |
|---|---|
| 方案内容 | 定级对象与范围、测评阶段（准备 / 方案编制 / 现场测评 / 分析与报告）、测评项与标准条款对照、差距整改清单与优先级、复测安排、交付物清单 |
| 架构描述 | 不画产品架构，改画「测评对象边界图 + 数据流/访问关系」，说明哪些系统纳入范围 |
| 可验证指标示例 | 测评项覆盖率、高危问题整改闭环率、报告交付时限、复测通过判据（按测评要求条款） |
| 常见坑 | 把测评方案写成安全产品方案；不写测评机构资质【待补】；承诺「保证通过测评」（结果不可承诺）；标准条款对照表缺条款号 |
| 边界 | 测评结论由具备资质的测评机构出具，技术方案不得替其下结论 |

### 4. 数据安全与数据治理

| 维度 | 要素 |
|---|---|
| 方案内容 | 数据资产与分级分类、采集/传输/存储/使用/共享/销毁各环节措施、权限模型与审批、加密与脱敏、审计与追溯、备份与恢复 |
| 架构描述 | 数据流向图 + 分级分类表（类别 / 敏感级别 / 存放位置 / 访问角色 / 保留期） |
| 可验证指标示例 | 分类分级覆盖率、脱敏规则命中率、审计日志留存期、备份 RPO/RTO、恢复演练成功率 |
| 常见坑 | 只讲加密不讲密钥管理；分级表没有责任人和存放位置；把「数据不出域」写成口号却无技术措施；个人信息处理不提法律依据核对 |

### 5. 运维服务与安全运营

| 维度 | 要素 |
|---|---|
| 方案内容 | 服务范围与期限、故障分级与响应时限、巡检计划、监控指标与告警阈值、工单与升级路径、月度/季度报告、知识库与移交 |
| 架构描述 | 服务流程图 + 角色职责矩阵，而非产品架构 |
| 可验证指标示例 | 响应/到场/解决时限（分故障等级）、巡检频次、告警处置闭环率、报告提交周期、服务可用率 |
| 常见坑 | 「7×24 响应」没有分级和口径；时限承诺无法举证；报告模板没有字段；备件与替换流程缺失 |

### 6. 软件开发 / 平台建设

| 维度 | 要素 |
|---|---|
| 方案内容 | 需求条目与优先级、功能模块划分、技术架构与组件选型、接口与数据模型、开发与测试流程、上线与回退、验收测试用例、源码与文档交付 |
| 架构描述 | 逻辑架构 + 组件清单 + 接口表（接口编号 / 调用方 / 数据 / 频率 / 鉴权方式） |
| 可验证指标示例 | 功能点覆盖率、并发用户数与响应时间、缺陷分级与遗留上限、接口联调通过率、文档交付项数 |
| 常见坑 | 只写技术栈不写需求映射；性能指标与测试大纲不一致；不写源码与知识产权归属（按招标文件）；上线回退缺位 |

## 三、可验证指标的写法示例

| 指标 | 指标值（示例，须按招标/投标材料填） | 验证方法 | 判定准则 | 验证阶段 |
|---|---|---|---|---|
| 设备吞吐 | 【待确认：检测报告第 X 页】 | 按测试大纲 T-03，用流量测试仪施加标称负载，记录转发速率与丢包 | 达到标称值且丢包在招标允许范围内 | 到货验收 |
| 故障切换 | ≤ 30 秒【以投标承诺为准】 | 主设备断电，记录业务恢复时间 | 三次测试均不超过承诺值 | 实施阶段 |
| 日志上报 | 关键设备日志上报完整率 ≥ 99%【以投标承诺为准】 | 抽样比对设备本地日志与平台接收日志 | 抽样差异在允许范围内 | 试运行 |
| 响应时限 | 一级故障 15 分钟响应【以投标承诺为准】 | 工单系统时间戳抽查 | 工单记录满足分级时限 | 服务期 |
| 备份恢复 | RPO / RTO【以投标承诺为准】 | 按演练脚本做一次恢复演练 | 在承诺时间内恢复且数据完整 | 验收 / 演练 |

> 表中所有数值只是**占位示例**。正式方案里必须换成招标文件要求或投标人真实承诺，并补上佐证材料编号；换不了就写【待确认】。

## 四、写「方案内容」时的自检十问

1. 这一段对应评分表哪一条？说不出来就删。
2. 是在讲「本项目怎么做」，还是抄产品彩页？
3. 出现的设备型号、数量，和清单对得上吗？
4. 出现的指标，测试大纲里测不测？怎么测？
5. 有没有写清谁负责、什么时候做、交付什么？
6. 有没有把「待确认」写成「满足」？
7. 引用的标准，招标文件指定版本了吗？核对了吗？
8. 有没有承诺做不到或不可控的结果（保证中标、保证通过测评、零风险）？
9. 附件索引有编号吗？材料真的具备吗？
10. 这段删掉，评委会不会少一个给分依据？如果会，必须保留并加标题。

## 五、最容易导致「响应不实」的五种写法

| 写法 | 风险 | 替代写法 |
|---|---|---|
| 「支持 10 Gbps 吞吐」（无出处） | 被要求提供检测报告时无法举证 | 「吞吐指标见附件 X 检测报告第 Y 页【待补：由投标人提供】」 |
| 「已服务 200 家政府客户」 | 业绩数量无法核实 | 「同类项目业绩见附件 X【待补：合同或验收证明】」 |
| 「完全满足招标所有技术要求」 | 与参数响应表里的「待确认」冲突 | 「逐条响应情况见参数响应表；待确认项已列入待补清单」 |
| 「符合 GB/T XXXXX-20XX」（版本未核） | 版本失效或与招标指定不一致 | 「按招标文件指定版本执行【待确认：版本核对】」 |
| 「保证一次性通过等保三级测评」 | 测评结果由第三方机构判定，不可承诺 | 「按测评要求逐项准备并配合复测，结论以测评机构报告为准」 |
