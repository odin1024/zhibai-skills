# 异常处理

## 输入类问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 参数贴进来是一大段，没有分行 | PDF 复制丢失换行 | 让模型按「序号 + 参数名 + 指标」重新切分；切不准时补充原文截图 |
| 表格列错位，数字串行 | PDF 表格结构丢失 | 按「参数名 → 指标 → 单位」三段式重新对齐；无法判断的格子留空标「待核」 |
| OCR 后数字明显不对（如 10Gbps 变成 l0Gbps） | 字符混淆 | 全表数值二次抽检；把可疑项列成「待核数值清单」 |
| 招标文件有多个版本 | 版本混乱 | 以招标编号 + 发布日期最新版为准；响应表首行注明依据版本 |
| 参数编号重复 | 原文排版问题 | 按出现顺序重编，保留「原编号：X」备注 |

## 判定类问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 无法判断某条是否★条款 | 招标文件未明示 | 查「评标办法」「投标人须知前附表」；仍无法确认时标「疑似实质性条款」并提示澄清 |
| 产品资料查不到对应参数 | 资料不全 | 判定为「待确认」，进风险清单，不填「无偏离」 |
| 同一参数在两处要求不一致 | 招标文件自身矛盾 | 按更严格的一条响应，同时在风险清单提示「原文冲突，建议澄清」 |
| 定量参数单位对不上 | 招标用 Mbps，彩页用 MB/s | 统一换算后再比较（1 MB/s = 8 Mbps），换算过程写进备注 |
| 参数含「等」「之类」等开放表述 | 范围不明确 | 按已列项响应，风险清单提示「开放性表述，建议按最不利情形准备」 |

## 输出类问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 表格太宽，贴进 Word 后错行 | 列内容过长 | 缩短「招标要求」列（删修辞留指标）；或改输出「一行一条」的清单式 |
| 参数太多，一次输出被截断 | 单次长度限制 | 分批输出，每批结尾给「已完成 X 条，剩余 Y 条」，下一批接着做 |
| 编号和招标文件对不上 | 拆句后自增编号 | 改用「父编号-序号」形式（如 3.2.3-1），并保留原编号 |
| 输出里混进了方案性内容 | 模型自行扩展 | 明确要求「只做响应表，不写方案」；删掉方案段落 |

## 流程类问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 做到一半断了 | 会话中断 | 把已完成的表贴回来，说明「从第 X 条继续」 |
| 改了产品型号，要重做 | 参数基准变了 | 只重跑「投标响应」和「偏离」两列，招标要求列不动 |
| 评审反馈某条被认定为未响应 | 表述不清 | 补具体数值 + 证明材料页码；把「满足」改成「实测值 + 测试条件」 |
| 时间不够，只能做一部分 | 投标截止临近 | 优先保证★条款 100% 覆盖，普通条款可先出简表，标注「详表后补」 |

## 拒绝执行的情况

以下要求会被拒绝，并说明原因：

1. **要求把不满足的参数写成「满足」**——提供虚假材料，法律风险
2. **要求编造证明材料或页码**——同上
3. **要求代签、代盖章**——伪造印章
4. **要求改写招标原文使其对我方有利**——未实质性响应
5. **要求判断某项目是否「内定」或预测中标结果**——无法判断，且涉及不正当竞争
