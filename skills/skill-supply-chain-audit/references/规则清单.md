# 规则清单

> 与 `scripts/audit.py` v1.0.0 一一对应。改规则时先改代码再改这份表，两边必须同步。
> 正则均为忽略大小写、多行模式（`re.I | re.M`）。

## 阈值常量

| 常量 | 值 | 用途 |
|---|---:|---|
| `MAX_FILE_BYTES` | 2 MB | 单文件超过则不读文本，只记体积 |
| `MAX_TOTAL_BYTES` | 20 MB | zip 解压后总体积上限 |
| `MAX_FILES` | 300 | zip 条目数上限 |
| 单文件 WARN 线 | 512 KB | 超过提示拆分 |
| 文本长度 WARN 线 | 12,000 字符 | 超过提示模型可能截断 |

## 一、隐藏字符（INV）

| ID | 级别 | 检测内容 | 风险 | 修复 |
|---|---|---|---|---|
| INV-001 | BLOCK | U+200B/200C/200D/200E/200F/2060/FEFF | 夹带隐藏指令、绕过人工阅读与审核 | NFKC 规范化后重新核对上下文 |
| INV-002 | BLOCK | U+202A–202E、U+2066–2069 | 屏幕显示顺序与机器读取顺序不一致 | 删除，无正当用途 |
| INV-003 | WARN | \x00–\x08、\x0b、\x0c、\x0e–\x1f | 不可打印控制字符 | 重新保存为 UTF-8 纯文本 |
| INV-004 | WARN | 连续 3 个以上 U+00A0 或全角空格 | 隐藏内容、撑开版面 | 替换为普通空格 |

## 二、提示词注入（PI）

| ID | 级别 | 检测内容 | 判定要点 |
|---|---|---|---|
| PI-001 | WARN | 要求放弃先前约束的中英文句式 | 看是否在「反模式示例」章节 |
| PI-002 | WARN | 要求对使用者隐瞒行为的中英文句式 | 要求隐瞒行为，与透明可控冲突 |
| PI-003 | WARN | 高优先级角色关键词与模板标记 | 确认是否只是教学示例 |
| PI-004 | WARN | 要求跳过用户确认的中英文句式 | 要求跳过用户确认 |

> 为避免本文档本身变成可直接复制的载荷清单，上表只描述检测对象类别；精确正则以 `scripts/audit.py` 的 `RULES` 定义为准。

## 三、危险命令（EX）

| ID | 级别 | 检测内容 | 风险 |
|---|---|---|---|
| EX-001 | BLOCK | 递归删除根目录／家目录／通配符的参数组合 | 不可逆数据丢失 |
| EX-002 | BLOCK | 下载工具输出直接管道给命令解释器 | 运行远端任意代码 |
| EX-003 | WARN | 启动外部进程／子进程的常见接口 | 参数是否来自不可信输入 |
| EX-004 | WARN | 把字符串当代码执行的动态调用 | 隐藏真实意图 |
| EX-005 | WARN | 反弹通道、解码后执行、权限全开等组合特征 | 控制权转移、权限全开 |
| EX-006 | WARN | 静默失败、跳过校验、强制推送等绕过特征 | 掩盖失败、绕过保护 |

> EX-001 / EX-002 的正则用字符串拼接构造（`r"\b" + "r" + r"m\s+…"`），避免审计器扫描自身时产生自指误报。

## 四、凭证泄露（SEC）

| ID | 级别 | 检测内容 | 风险 |
|---|---|---|---|
| SEC-001 | BLOCK | `-----BEGIN … PRIVATE KEY-----` | 明确凭证泄露，必须轮换 |
| SEC-002 | BLOCK | `ghp_`/`gho_`/`skh_`/`sk-`/`AKIA`/`xox*` 后跟 20 位以上字母数字 | 疑似真实 Token；占位符不命中 |
| SEC-003 | WARN | `.aws/credentials`、`.ssh/id_`、`.npmrc`、`.netrc`、`.git-credentials`、`.env` | 是否读取或外传本机凭证 |
| SEC-004 | WARN | `key/secret/token/password = '具体值'`（≥12 字符） | 硬编码凭据 |
| SEC-005 | WARN | 从环境变量读取含 KEY/TOKEN/SECRET/PASS 的变量 | 需追查后续是否写入日志或请求 |

## 五、外发行为（NET）

| ID | 级别 | 检测内容 | 说明 |
|---|---|---|---|
| NET-001 | WARN | 常见 HTTP 客户端调用 | 确认目标域名与发送字段 |
| NET-002 | INFO | 文件内所有 `http(s)://` 链接 | 规则本身登记为 WARN，但 `scan_text` 按文件聚合成一条 INFO 输出，避免刷屏 |
| NET-003 | BLOCK | 常见带外数据收集（OAST）服务域名 | 带外数据收集域名，无正当用途 |
| NET-004 | WARN | 实时通道与消息推送接口 | 实时通道或消息推送 |

> NET-004 不含裸词 `webhook`，避免 OAST 域名被重复报两次。

## 六、包结构（ZIP / SIZE / META）

| ID | 级别 | 检测内容 | 风险 |
|---|---|---|---|
| ZIP-000 | BLOCK | 不是合法 zip | 包损坏或被伪装 |
| ZIP-001 | BLOCK | 条目数 > 300 | 压缩炸弹或夹带大量无关文件 |
| ZIP-002 | BLOCK | 绝对路径、`../`、`C:` 开头的条目名 | 解压写到目标目录之外 |
| ZIP-003 | WARN | 外部属性标记为符号链接 | 后续写入被重定向 |
| ZIP-004 | BLOCK | flag_bits 加密位 | 静态审计存在盲区 |
| ZIP-005 | BLOCK | 压缩比 > 200:1 | 压缩炸弹 |
| ZIP-006 | WARN | 解压后总体积 > 20 MB | 技能包通常以文本为主 |
| SIZE-001 | WARN | 单文件 > 512 KB | 客户端会截断长文档 |
| SIZE-002 | WARN | 单个文本 > 12,000 字符 | 尾部内容可能不被模型读到 |
| META-010 | WARN | `SKILL.md` 缺 YAML frontmatter | 客户端可能无法识别触发条件 |
| META-011 | WARN | frontmatter 缺 `name`/`description`/`slug`/`version` | 发布时必填项缺失 |

> `META-001`（frontmatter 分隔符）与 `META-002`（URL 路径穿越）在规则表中有定义，
> 但 `scan_text` 对它们做了特殊处理：前者跳过（只作结构占位），后者已被 SEC/NET 类覆盖。
> 保留定义是为了后续扩展，不产生独立发现。

## 结论与退出码

| 条件 | 结论 | 退出码 |
|---|---|---:|
| 存在任意 BLOCK | 阻断 | 2 |
| 无 BLOCK 但有 WARN，且启用 `--strict` | 需人工确认 | 1 |
| 无 BLOCK、有 WARN、未启用 `--strict` | 需人工确认 | 0 |
| 只有 INFO 或无发现 | 通过 | 0 |
| 目标不合法 | — | 3 |

## 怎么新增一条规则

1. 在 `scripts/audit.py` 的 `RULES` 区用 `rule(id, level, cat, pattern, desc, fix)` 注册
2. ID 用「类别前缀 + 三位序号」，不要复用已有编号
3. 级别判断标准：**只有正常中文技能文档里绝无正当用途的特征才设 BLOCK**，其余一律 WARN
4. 在 `scripts/selftest.py` 里补一组构造样本，能命中且干净包不误报
5. 同步更新本表与 `SKILL.md` 的规则速查表
6. 跑 `python scripts/selftest.py`，必须 100% 通过

## 已知局限

- 正则匹配单行，跨行拼接的恶意字符串可能漏检
- 只扫白名单后缀的文本文件，不解析 PDF / 图片 / 二进制
- 无法识别同形异义字、HTML 实体、运行时解码
- 中文语境下的「软性诱导」（例如通篇劝用户关掉安全设置）没有明显特征词，扫不出来

这些局限不是缺陷清单，而是**报告里必须写清的边界**，见 `references/威胁模型.md` 第四节。
