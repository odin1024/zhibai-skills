# 威胁模型：Agent Skill 供应链

> 这份文档解释「为什么这么判」，不是规则表。规则 ID、正则与级别见 `references/规则清单.md`。
> 用途：审计技能在解读报告时查依据；也可作为团队做技能入库评审的培训材料。

---

## 一、为什么技能是特殊的攻击面

普通软件要编译、要安装、要启动，中间有很多次「用户确认」。Agent Skill 没有这些环节：

- 一份 `SKILL.md` 放进技能目录，模型下次会话就会读到它
- 内容是自然语言，模型被训练成「认真遵循指令」，而不是「把它当不可信数据」
- 没有沙箱、没有权限声明、没有签名校验，用户通常也不会逐字通读
- 技能可以引用 `references/`、脚本、外部链接，加载链条比看上去长

所以技能供应链的核心风险不是「代码有漏洞」，而是**一段被模型当作指令执行的不可信文本**。这也是为什么本审计器把隐藏字符和注入话术放在最前面，而不是先查命令。

可参考的公开分类：OWASP Top 10 for LLM Applications 里的提示词注入（LLM01）与供应链风险（LLM05）；CWE-506（Embedded Malicious Code）、CWE-22（路径穿越）、CWE-798（硬编码凭据）。这里只作概念对照，不套用具体版本的编号细节。

---

## 二、六类威胁逐条拆解

### 1. 不可见字符与文本方向控制（INV）

**原理**
Unicode 里有一批不产生可见字形的字符：零宽空格 U+200B、零宽不连字 U+200C、零宽连字 U+200D、词序控制 U+202A–U+202E、隔离符 U+2066–U+2069、BOM U+FEFF。它们不会改变渲染出来的文字，但会改变模型实际读到的字节流。

双向控制符更危险：它可以让编辑器里显示的顺序和模型读取的逻辑顺序不一致。攻击者把一段恶意指令包在 RLO/LRO 里，人工在屏幕上看到的是正常句子，模型读到的是另一串。

**真实形态**
- 在一段正常说明中间插入零宽字符分隔的隐藏指令
- 用 U+202E 把一段覆盖先前指令的话术伪装成看起来像普通中文的字符串
- 在 Markdown 链接文字里夹零宽字符，让域名看起来是官方的

**为什么定 BLOCK**
正常的中文技能文档没有任何理由使用这些字符。零宽空格不是排版工具，双向控制符只用于阿拉伯语／希伯来语混排。命中即视为异常，几乎没有误报空间。

**修复**
用 Unicode 规范化（NFKC）清理后重新核对上下文；要求作者提供干净版本。不要只删掉字符就放行——要确认被删字符周围原本藏了什么。

**绕过手法（静态扫描的局限）**
攻击者可以改用同形异义字（如西里尔字母 а 冒充拉丁 a）、用 HTML 实体、或把指令编码进 base64 让运行时再解码。这些不在 INV 规则覆盖范围，属于第四节说的边界。

---

### 2. 提示词注入与越权指令（PI）

**原理**
技能正文和用户输入在模型眼里都是文本。恶意技能会写覆盖先前指令、要求对使用者隐瞒行为、要求跳过确认这几类话术，试图把自己的优先级提到系统指令之上，或把自己做的事藏起来。

**四类话术**

| 类型 | 典型句式 | 意图 |
|---|---|---|
| 覆盖指令 | 要求放弃先前约束的中英文句式 | 让模型放弃原有约束 |
| 隐瞒行为 | 要求对使用者隐瞒的中英文句式 | 让输出里不出现可疑动作 |
| 伪造角色 | 高优先级角色关键词与模板标记 | 伪装成更高优先级的消息 |
| 跳过确认 | 要求跳过用户确认的中英文句式 | 扩大实际执行权限 |

**为什么定 WARN 而不是 BLOCK**
讲安全、讲注入防御、讲反模式的技能，正文里**必然**会出现这些句式。直接阻断会大量误杀。所以这一类是「必须看上下文」，报告要写清命中的是说明文字还是可执行指令。

**判定要点**
看命中位置所在的章节标题：若落在「反模式」「错误示例」「不要这样写」之下，降级；若落在「执行步骤」「工作流」「安装说明」里，升级为实质风险。

---

### 3. 危险命令与执行面（EX）

**原理**
技能本身是文本，但它可以指示 Agent 去执行命令，也可以附带脚本。危险的不是字符串出现，而是**字符串出现在什么位置**。

**六类特征**

| 特征 | 后果 |
|---|---|
| 递归删除根／家目录／通配符 | 不可逆数据丢失 |
| 下载内容管道给 shell | 等价于运行远端任意代码 |
| 启动外部进程 | 参数若来自不可信输入即可被注入 |
| 动态执行字符串、编码命令 | 隐藏真实意图，绕过审阅 |
| 反弹 shell、解码后执行、全开放权限 | 直接的控制权转移 |
| 静默失败、跳过校验、强制推送 | 掩盖失败、绕过保护 |

**为什么 EX-001 / EX-002 定 BLOCK**
递归删除根目录、把下载内容直接管道给解释器，这两类在技能里没有正当用途：技能是文档，不是安装脚本。即使作者声称「只是示例」，也不该把可直接复制执行的完整命令写进正文。其余四类定 WARN，因为启动外部进程、读取环境变量这类能力在合法工具里确实存在。

**修复**
删除命令；确需外部执行的，改为固定参数 + 白名单 + 执行前向用户确认，并在文档里写清会碰哪些文件。

---

### 4. 凭证、密钥与敏感路径（SEC）

**原理**
两类问题要分开：

- **真实凭证泄露**：私钥 PEM、真实 Token 被硬编码进技能包。这是事故，不是风险提示。
- **读取凭证的能力**：技能从环境变量读 Key、引用 `~/.ssh`、`.aws/credentials`。这本身合法，危险在于读取之后做什么。

**为什么 SEC-002 要求 Token 后跟 20 位以上字符**
`skh_xxx`、`YOUR_KEY_HERE`、`ghp_…` 这类占位符在文档里非常常见，若按前缀就报，会满屏误报。规则要求前缀后跟足够长的字母数字串才命中，命中后仍要人工确认是不是示例值。

**判定要点**
- 私钥 PEM 头 → 一律 BLOCK，并要求**轮换密钥、检查 Git 历史**（删文件不等于没泄露过）
- 疑似真实 Token → BLOCK，报告里不要贴出完整值，只给文件行号和脱敏片段
- 环境变量读取 → WARN，关键是追「读取之后有没有写日志、拼进 URL、发给外部」

**修复**
改从环境变量读取；示例值换成明显占位符；把已泄露的凭证吊销并重发。

### 5. 外发行为与带外数据收集（NET）

**原理**
技能可以指示 Agent 发起网络请求。正常用途是查文档、调 API；恶意用途是把本地文件内容、环境变量、会话上下文送出去。

**OAST 域名为什么单独定 BLOCK**
常见带外数据收集（OAST）托管服务的唯一常见用途就是接收回连数据（精确域名清单见 `scripts/audit.py` 的规则表，本文不复述完整列表）。它们出现在技能正文里没有正当理由——即使是安全测试技能，也该由用户运行时自己指定目标，而不是硬编码在公开分发的文档里。

**其余三类定 WARN 的原因**
常见的 HTTP 客户端调用、外部链接与实时通道都是合法能力。要看的是：目标域名是谁的、发送了什么字段、有没有把本地文件内容拼进请求。

**判定要点**
短链、IP 直连、随机子域、刚注册的域名要展开后判断；白名单域名（官方文档、标准规范站）可降级，但要在报告里写出依据。

### 6. 包结构与元数据（ZIP / SIZE / META）

**为什么压缩包必须先扫后解压**

| 攻击 | 原理 | 后果 |
|---|---|---|
| 路径穿越 | 条目名含 `../` 或绝对路径 | 解压写到目标目录之外 |
| 符号链接 | zip 外部属性标记为 symlink | 后续写入被重定向到宿主机任意位置 |
| 加密条目 | flag_bits 置位 | 静态审计读不到内容，等于留了盲区 |
| 压缩炸弹 | 极小压缩包展开成极大文件 | 耗尽磁盘或内存 |
| 文件数爆炸 | 塞入成千上万个条目 | 拖垮扫描与安装流程 |

**体积为什么也算风险**
多数 Agent 客户端在加载长文档时会截断（常见在约 8000 字符量级）。一个 18 KB 的 `SKILL.md` 看起来内容详实，实际上模型可能只读到前半段——后半段如果被故意塞入指令，用户通读时看得见，模型却读不到，或者反过来。所以超过阈值给 WARN，建议拆成 `references/` 分层文件。

**元数据**
`SKILL.md` 缺 frontmatter 或必填字段，客户端可能无法正确识别触发条件，也可能被平台重新分类。这不是安全漏洞，但属于可用性风险，归在 WARN。

## 三、误报是怎么控制的

审计器的可信度取决于误报率。四项工程设计：

1. **按证据定位**：每条发现给文件 + 行号 + 命中片段。没有证据的不报。
2. **占位符豁免**：Token 规则要求足够长度，前缀后面跟 `xxx` 不命中。
3. **URL 汇总**：外链规则不逐条刷屏，按文件聚合成一条 INFO。
4. **级别分层**：只有「正常文档里绝无正当用途」的特征才定 BLOCK，其余一律 WARN。

实测：用审计器扫描本项目自己的六个技能（含 18 KB 级 `SKILL.md` 与六份深度知识库），结果全部为「通过」，BLOCK 0 / WARN 0，仅各有一条外链 INFO。七组构造样本自检 7/7 通过。

**但误报仍然存在**，尤其是教学类、安全类技能。所以流程规定：WARN 必须逐条核对上下文并写出依据，不能笼统说「请自行判断」，也不能一键全降级。

## 四、覆盖边界（报告末尾必须照抄）

静态审计能发现：不可见字符、提示词注入话术、危险命令特征、硬编码密钥、
敏感路径引用、外发请求与 OAST 域名、压缩包结构攻击、frontmatter 缺失、体积异常。

静态审计不能发现：混淆后运行时才拼接出来的恶意逻辑、二进制文件里的行为、
依赖包供应链投毒、需要联网才触发的下载、社会工程诱导用户手动执行的操作、
以及任何「看起来完全正常但指令本身有害」的内容。

结论只能作为安装前的第一道筛子，不能替代沙箱执行、来源核验和人工通读。

## 五、人工复核十条清单

扫描通过之后，仍建议花两分钟过一遍：

1. 仓库创建时间、提交历史、作者是否可追溯
2. README 里的安装命令是否和正文一致
3. 有没有 `scripts/` 目录，脚本是否被正文要求执行
4. `references/` 里有没有和技能主题无关的章节
5. 所有外部域名是否属于可信主体
6. 是否要求读取工作区以外的路径
7. 是否要求关闭确认、静默执行、跳过校验
8. 是否要求把结果发到某个地址
9. 有没有要求对使用者隐瞒行为的表述
10. 版本更新日志里有没有突然新增的网络或文件权限

## 六、给团队用的门禁建议

| 环节 | 做法 |
|---|---|
| 入库 | `audit.py --json --strict`，BLOCK 直接拒收，WARN 转人工 |
| 留档 | 每次扫描输出 Markdown 报告，随技能版本一起存档 |
| 复检 | 技能升级版本时重新扫描，不要沿用旧报告 |
| 白名单 | 对确认安全的 WARN 建立按「文件+行+规则 ID」的白名单，不要整包放行 |
| 应急 | 发现真实 Token 或私钥，先吊销凭证再下架，不要只删文件 |
