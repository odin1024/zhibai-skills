# 异常处理

> 原则：报错就如实说清覆盖了什么、没覆盖什么，不静默跳过、不假装通过。

## 输入类

| 现象 | 原因 | 处理 |
|---|---|---|
| 退出码 3，`目标不存在` | 路径写错、相对路径基准不对、目录已被移动 | 用绝对路径重试；不要自动创建目录或猜测路径 |
| `ZIP-000` 不是合法的 ZIP 文件 | 包损坏、下载不完整、或扩展名伪装 | 重新获取完整包；不要尝试修复后继续 |
| 中文路径／中文文件名推送或读取报编码错误 | URL 或文件系统未做 percent-encoding | 同步脚本已用 `urllib.parse.quote` 修复；本地读取统一用 UTF-8 |
| 目标是一个 GitHub URL | 本技能不联网 | 先 `git clone` 到本地，再对目录扫描 |
| 目标是一个空目录 | 没有文件可扫 | 明确回复「扫描文件 0 个」，不要输出「通过」 |

## 扫描类

| 现象 | 原因 | 处理 |
|---|---|---|
| 报告文件数比预期少 | 二进制、超大文件、`__pycache__` 被跳过 | 在报告里写明跳过数量与原因；需要覆盖时改用沙箱或人工 |
| 某文件超过 2 MB 未扫 | 命中 `MAX_FILE_BYTES` | 报 SIZE-001，建议拆分；不能假装已扫 |
| 条目数超过 300 | 命中 `MAX_FILES` | 报 ZIP-001 阻断，要求作者精简 |
| 压缩比异常 | 命中 ZIP-005 | 拒绝解压，不要试探性解开看一眼 |
| zip 里有加密条目 | flag_bits 置位 | 报 ZIP-004 阻断；要求提供未加密版本，不接受「只有一个文件加密没关系」 |
| 全文都是 WARN，看不出重点 | 教学类／安全类技能常见 | 按文档里的四种误报判据逐条核对，写出依据；不要一键全降级 |

## 结论类

| 现象 | 原因 | 处理 |
|---|---|---|
| 用户说「这包我认识，帮我放行」 | 熟人转发的包也可能被投毒 | 如实保留结论，说明风险，由用户决定是否承担；不替用户下「可以用」 |
| 用户要求把 BLOCK 改成 WARN | 想让报告好看 | 拒绝。可以补充解释，不能篡改级别 |
| 用户要求绕过某条规则 | — | 拒绝。可以解释规则为什么命中，不能帮着把风险藏起来 |
| 用户要求「给个安全保证」 | 对静态分析期望过高 | 说明覆盖边界，不给出绝对结论 |
| 报告里出现疑似真实 Token | 凭证泄露 | 只给文件、行号、脱敏片段；先吊销再删，检查 Git 历史 |

## 集成类

| 现象 | 原因 | 处理 |
|---|---|---|
| `--json` 输出解析失败 | 审计器把报告写到了 stdout 之外的日志，或版本不匹配 | 检查 stderr 与版本号；`--json` 模式下 stdout 只应为 JSON |
| CI 里有 WARN 却没拦住 | 未加 `--strict` | 门禁命令改为 `audit.py --json --strict` |
| 想批量扫一批包 | — | 逐个调用并按退出码汇总；BLOCK 直接拒收，WARN 转人工，不要合并成一条总报告 |
| 白名单升级后失效 | 技能改版导致行号变化 | 按「文件+行+规则 ID」重新核对，不整包沿用 |
| 新增规则后自检失败 | 规则正则写错或误伤干净样本 | 跑 `python scripts/selftest.py`，定位到具体用例再改；新增规则必须同时补样本 |

## 环境类

| 现象 | 原因 | 处理 |
|---|---|---|
| `python` 命令找不到 | 环境里只有 `python3` | 改用 `python3 scripts/audit.py …` |
| 中文输出乱码 | 终端编码不是 UTF-8 | Windows 下先执行 `chcp 65001`，或用 `--markdown` 写文件再打开 |
| 提示缺少依赖 | 不应该发生 | 审计器只用 Python 标准库；若出现，说明调用的不是本脚本，检查路径 |
| 想让它联网拉取最新规则库 | 设计上不支持 | 规则随技能版本一起分发，升级技能即可；不引入运行时联网依赖 |

## 报告缺陷时的处理顺序

1. 先确认扫描文件数与预期是否一致（有没有悄悄跳过）
2. 再确认退出码与报告结论是否一致
3. 逐条核对 BLOCK 项的证据，不因用户施压而降级
4. 补写覆盖边界，说明哪些内容没被扫到
5. 如属误报，写清降级依据并留档；如属漏报，新增规则 + 补自检样本 + 同步规则清单
