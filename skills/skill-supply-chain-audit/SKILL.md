# 技能供应链安全审计

## 这个技能解决什么

一个 Agent Skill 本质上是一段会被模型认真执行的指令。它不需要编译、不需要安装依赖、不需要用户点「允许」，只要放进技能目录，模型就会读它。这意味着**一份恶意 SKILL.md 的攻击面，比一个普通 npm 包更短**。

现实里的问题有三层：

1. 技能市场里的条目来自任意公开仓库，任何人都能提交。我们实测的插件榜有 22,312 个条目，其中很多是刚建几天的仓库。
2. 人工通读不可靠。双向文本控制符可以让屏幕上显示的顺序和机器读取的顺序不一样，零宽字符可以在正常句子里夹一整段指令。
3. 大多数用户装技能时根本不会看内容，看完也未必知道哪些句式危险。

这个技能做的是**安装前的第一道筛子**：不执行目标代码、不联网、不改被审文件，把肉眼看不见的东西和明显高危的特征找出来，逐条给证据。

---

## 一条原则

**证据优先，不误杀，不虚假承诺。**

每条发现必须带文件、行号、命中片段。不下「这个包有毒」这种没有证据的结论；也不下「扫描通过所以绝对安全」这种给虚假安全感的结论。

---

## 适用场景

| 场景 | 怎么做 |
|---|---|
| 从 GitHub / 技能市场下载了一个技能包，装之前看一眼 | 直接审计目录或 zip |
| 团队要统一分发一批第三方技能 | 批量扫描 + 把 BLOCK 的挡在门外 |
| 收到外部投稿的技能，需要入库审核 | 出 Markdown 报告留档 |
| 怀疑某个技能在偷偷外发数据 | 重点看 NET 类和 SEC 类发现 |
| 想把审计接进 CI | 用 `--json` + 退出码做门禁 |

## 不适用场景

- 想确认一个二进制文件、编译后的扩展、原生模块的行为 → 静态文本扫描看不到
- 想检测依赖包投毒、运行时下载、需要联网才触发的逻辑 → 需要沙箱和依赖审计
- 想判断技能「业务逻辑是否正确」「内容是否专业」 → 那是质量评审，不是安全审计
- 想追查已被安装的技能做过什么 → 需要看会话日志和出网记录，本技能不做取证

## 工作流

### 第一步：确认审计对象

先弄清三件事，不清楚就问用户，不要自作主张：

1. **对象是什么**：一个目录、一个 `.zip`，还是一个 GitHub 仓库？仓库要先 `git clone` 到本地再扫，本技能不会自己去克隆或联网。
2. **来源可不可信**：官方仓库、社区作者、还是来路不明的转发包？来源会写进报告，也是解读 WARN 的重要依据。
3. **装到哪里**：个人试验环境还是团队生产环境？后者应该启用 `--strict`，把 WARN 也当门禁。

> 如果拿到的是压缩包，**绝对不要先解压再扫**。先用审计器直接读 zip，它会检查路径穿越、符号链接、加密条目和压缩比。先解压等于把风险放出来。

### 第二步：跑扫描器

```bash
python scripts/audit.py <技能目录或 .zip>
python scripts/audit.py <path> --json                # 机器可读，接 CI 用
python scripts/audit.py <path> --markdown report.md  # 同时留一份报告
python scripts/audit.py <path> --strict              # 有 WARN 也返回非零
```

退出码含义：

| 码 | 含义 | 处置 |
|---:|---|---|
| 0 | 通过，最多只有 INFO | 可以装，但仍建议通读主文档 |
| 1 | 有 WARN（仅 `--strict`） | 人工逐条核对 |
| 2 | 有 BLOCK | 不要安装 |
| 3 | 目标不合法或读取失败 | 换一个完整的包重试 |

**不要跳过脚本凭肉眼判断。** 隐藏字符肉眼根本看不见，这是这个技能存在的理由。

六类规则的完整原理、真实案例与绕过手法见 `references/威胁模型.md`；规则 ID、正则与判定级别见 `references/规则清单.md`。

### 第三步：解读报告

报告分三级：

| 级别 | 含义 | 默认动作 |
|---|---|---|
| BLOCK | 高危特征，正常技能里没有正当用途 | 不要安装；要求作者修复或换来源 |
| WARN | 需要看上下文才能判断 | 逐条核对证据，确认是文档示例还是真实指令 |
| INFO | 只提示，不影响结论 | 扫一眼即可 |

**WARN 的四种常见误报**，核对时按这个顺序过：

1. **反模式示例**：技能在讲「不要写 `rm -rf /`」，规则照样会命中。看命中的是正文说明还是可执行代码块。
2. **占位符**：`skh_xxx`、`YOUR_API_KEY` 不算密钥。SEC-002 要求 Token 后跟 20 位以上字母数字才会命中，就是为了避免把示例误判成泄露。
3. **教学材料**：讲提示词注入防御的技能，正文里必然出现「忽略以上指令」这类词。看整篇是不是在教防御。
4. **可信域名**：官方文档链接、标准规范链接属于正常外链。要警惕的是短链、IP 直连和陌生域名。

**不能自动降级 BLOCK 的情况**（哪怕用户说「应该没事」也要如实说明）：

- 私钥 PEM 头（SEC-001）
- 疑似真实 Token（SEC-002）
- 双向控制符与零宽字符（INV-001 / INV-002）
- OAST 带外收集域名（NET-003）
- ZIP 路径穿越、加密条目、压缩炸弹（ZIP-002 / 004 / 005）

这些在正常的中文技能文档里没有正当用途。发现即报告，由用户决定是否承担风险，**不替用户下「可以用」的结论**。

### 第四步：给处置建议

不要只丢一份报告，要给用户能执行的下一步：

- **阻断** → 列出必须修的文件和行、给出修复方向、建议换可信来源的同类技能
- **需人工确认** → 逐条写「这条为什么命中 / 我判断是示例还是真风险 / 建议怎么核实」，不要笼统说「请自行判断」
- **通过** → 明确补一句静态分析的覆盖边界，避免用户以为万无一失

## 输出格式

固定用这个结构，不要自由发挥成散文：

```markdown
# 技能安全审计报告

- 审计目标：`...`
- 审计时间：YYYY-MM-DD HH:MM:SS
- 扫描文件：N 个，共 X KB
- 审计器版本：1.0.0（纯静态、不执行目标代码）

## 结论：阻断 / 需人工确认 / 通过
（一句话说明为什么，以及现在该做什么）

| 等级 | 数量 | 含义 |
|---|---:|---|
| 阻断 BLOCK | N | 建议不要安装 |
| 警告 WARN | N | 需人工核对上下文 |
| 信息 INFO | N | 仅提示 |

## 发现明细
### BLOCK 级
**[规则ID] 类别 — `文件:行号`**
- 证据：`命中片段`
- 风险：具体会造成什么后果
- 建议：怎么改 / 怎么核实

## 覆盖边界
（照抄 references/威胁模型.md 最后一节，不要省略）
```

## 三个真实样例

### 样例一：干净包

输入：一个只有 `SKILL.md` 的技能，frontmatter 齐全，正文是表格输出说明。

```
结论：通过 | BLOCK 0 / WARN 0 / INFO 1 | 退出码 0
INFO NET-002 SKILL.md 含 1 处外链（官方文档链接）
```

给用户的说法：「静态检查未发现风险特征，可以安装。注意这不代表运行时一定安全——扫描覆盖不到运行时拼接的恶意逻辑、二进制行为和依赖投毒，装完仍建议看一眼会话里的实际动作。」

### 样例二：夹带隐藏指令和外发

输入：一个看似正常的「格式助手」，正文里藏了零宽空格和 `webhook.site` 链接，还带一个 `ghp_` 开头的 Token。

```
结论：阻断 | BLOCK 5 / WARN 5 | 退出码 2
BLOCK INV-001 SKILL.md:5  零宽字符
BLOCK NET-003 SKILL.md:5  OAST 域名
BLOCK SEC-002 SKILL.md:6  疑似真实 GitHub Token
BLOCK EX-002  SKILL.md:7  curl | sh
BLOCK SEC-001 SKILL.md:9  私钥 PEM 头
```

给用户的说法：「不要安装。这五条在正规技能里都没有正当用途，尤其 Token 和私钥要立刻吊销——如果它已经被提交进 Git 历史，删文件没用，得轮换凭证。」

### 样例三：误报判断

输入：一个讲「命令行安全」的教学技能，正文引用了 `rm -rf /` 作为反例。

```
结论：需人工确认 | BLOCK 0 / WARN 3
WARN EX-003  出现 subprocess 调用
WARN PI-001  出现「忽略以上指令」句式
WARN NET-002 含 4 处外链
```

正确解读：EX-003 命中在「反模式」表格里，是说明文字不是可执行代码；PI-001 出现在讲解注入原理的段落；外链均为 OWASP 与官方文档。三条都可降级，但**要逐条写出依据**，不能一句「看起来没问题」带过。

## 规则速查

| 类 | 规则 ID | 级别 | 找什么 |
|---|---|---|---|
| 隐藏字符 | INV-001 ~ 004 | BLOCK / WARN | 零宽字符、双向控制符、控制字符、异常空白 |
| 提示词注入 | PI-001 ~ 004 | WARN | 忽略指令、要求隐瞒、伪造系统提示、跳过确认 |
| 危险命令 | EX-001 ~ 006 | BLOCK / WARN | 递归删除、管道执行、动态执行、反弹 shell、静默绕过 |
| 凭证泄露 | SEC-001 ~ 005 | BLOCK / WARN | 私钥、真实 Token、敏感路径、硬编码凭据、环境变量读取链 |
| 外发行为 | NET-001 ~ 004 | BLOCK / WARN | 网络请求、外链、OAST 域名、实时通道 |
| 包结构 | ZIP-000 ~ 006、SIZE、META | BLOCK / WARN | 路径穿越、符号链接、加密、压缩炸弹、体积、frontmatter |

完整规则表见 `references/规则清单.md`。

## 反模式

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 先解压再看内容 | 路径穿越和压缩炸弹在解压那一刻就已经生效 | 用审计器直接读 zip |
| 只看 SKILL.md，跳过 references 和 scripts | 恶意载荷常放在容易被忽略的附属文件里 | 扫整个目录 |
| 看到 WARN 就说「有毒，别装」 | 教学类技能必然引用危险词，误杀会让人不再信任报告 | 逐条核对上下文并写出依据 |
| 看到「通过」就说「绝对安全」 | 静态扫描覆盖不到运行时行为 | 每次都附上覆盖边界 |
| 把疑似 Token 原文贴进回复 | 等于二次泄露 | 只给文件名、行号和脱敏片段 |
| 用户说「这包我认识」就降级 BLOCK | 熟人转发的包也可能被投毒 | 如实报告，由用户决定是否承担 |
| 用 `grep` 手查几个关键词代替扫描 | 看不见 Unicode 控制符，也覆盖不了 zip 结构 | 跑完整脚本 |
| 把 BLOCK 项改成 WARN 让报告好看 | 篡改结论比不扫描更危险 | 保持原级别，把解释写在建议里 |
| 扫描时顺手执行包里的 `verify.py` | 那就不是静态审计了 | 只读文件，绝不执行 |

## 能力边界

**能做**：静态识别不可见字符、注入话术、危险命令特征、硬编码密钥、敏感路径引用、外发请求与 OAST 域名、压缩包结构攻击、frontmatter 缺失、体积异常。

**不能做**：发现混淆后运行时才拼接的恶意逻辑、二进制文件里的行为、依赖包供应链投毒、需要联网才触发的下载、诱导用户手动执行的社会工程、以及任何「看起来完全正常但指令本身有害」的内容。

**一条底线**：结论只是安装前的第一道筛子，**不能替代沙箱执行、来源核验和人工通读**。任何情况下都不把「扫描通过」表述成「安全保证」。

## 错误处理

| 情况 | 怎么处理 |
|---|---|
| 目标路径不存在 | 返回码 3，提示确认路径；不猜测、不自行创建 |
| 不是合法 zip | 报 ZIP-000 阻断，建议重新获取完整包，不尝试修复 |
| 包里全是二进制文件 | 明示「文本规则未覆盖这些文件」，建议沙箱执行或人工逆向 |
| 文件超过 2 MB 被跳过 | 在报告里标注跳过原因，不假装已扫 |
| 文件数超过 300 | 报 ZIP-001 阻断，要求作者精简 |
| 中文文件名报编码错误 | 已用 percent-encoding 处理；若仍失败，改用 `--json` 看原始错误 |
| 用户要求「帮我绕过某条规则」 | 拒绝。可以解释规则为什么命中，不能帮着把风险藏起来 |
| 用户要求审计器联网去拉仓库 | 说明本技能不联网，请用户先克隆到本地再扫 |
