# 常见问题

**Q1：扫描通过是不是就说明这个技能安全？**

不是。静态扫描只能发现「有特征的风险」，发现不了运行时才拼接的恶意逻辑、二进制文件行为、依赖包投毒、联网后才触发的下载，也发现不了「看起来完全正常但指令本身有害」的内容。通过的意思是「没找到已知危险特征」，不是「安全保证」。装完仍建议看一眼会话里的实际动作，尤其是在生产环境。

**Q2：为什么我自己的技能报了一堆 WARN？**

最常见的原因是它本身在讲安全、讲命令行、讲反模式，正文里引用了 `subprocess`、`忽略以上指令`、`rm` 这类词。审计器按单行正则匹配，不判断语义。逐条看证据：如果命中的是说明文字、表格里的错误示例、或教学段落，写清依据后降级即可。这不是误报 bug，是刻意把判断权留给人。

**Q3：哪些项绝对不能降级？**

五类：私钥 PEM 头（SEC-001）、疑似真实 Token（SEC-002）、双向控制符与零宽字符（INV-001/002）、OAST 带外收集域名（NET-003）、zip 的路径穿越／加密条目／压缩炸弹（ZIP-002/004/005）。这些在正常的中文技能文档里没有正当用途。发现即如实报告，由用户决定是否承担风险。

**Q4：为什么 `skh_xxx` 不算密钥泄露，但某个 `ghp_` 开头的字符串算？**

规则要求 Token 前缀后跟 20 位以上字母数字才命中。文档里的 `YOUR_API_KEY`、`skh_xxx`、`ghp_...` 都是占位符，按前缀就报会满屏误报。命中后仍要人工确认是不是示例值——如果确实是真凭证，先吊销再删，光删文件没用，还要检查 Git 历史。

**Q5：拿到 zip 包，能不能先解压再扫？**

不要。路径穿越和符号链接是在解压那一刻生效的，压缩炸弹也是。审计器会直接读 zip 的条目表和外部属性，不落地任何文件。先解压等于把风险放出来。

**Q6：能直接审 GitHub 仓库链接吗？**

不能，本技能不联网。请先 `git clone` 到本地再扫。这样也顺便能看提交历史、创建时间和作者信息——这些是人工复核清单里的前三项，静态扫描替代不了。

**Q7：二进制文件、图片、PDF 会不会被扫？**

不会。审计器只读白名单后缀的文本文件（md/py/js/json/yaml/sh 等），超过 2 MB 的文件也跳过。报告会说明扫描了多少文件，但不会假装已经覆盖了二进制。这类内容需要沙箱执行或人工逆向。

**Q8：`--strict` 该什么时候用？**

团队入库门禁、CI 流水线、装进生产环境之前。个人试验环境可以不加，WARN 逐条看一眼即可。注意 `--strict` 只改变退出码，不改变报告里的分级结论。

**Q9：为什么外链只报一条 INFO，不逐条列出来？**

避免刷屏。NET-002 按文件聚合成一条，告诉你「这个文件里有 N 处外链，需人工确认域名」。真正危险的外链由 NET-003 单独定 BLOCK。如果你需要逐条 URL，可以自己用 `--json` 拿原始数据再展开。

**Q10：这个技能会修改我审查的包吗？**

不会。全程只读：目录模式下只读文件文本和 stat 信息，zip 模式下只读条目表和内容，不解压、不写回、不执行包里任何脚本。它自己也不会联网。

**Q11：能帮我把某条 WARN 加进白名单，让报告干净点吗？**

可以建白名单，但要按「文件 + 行号 + 规则 ID」精确记录，不要整包放行，也不要把 BLOCK 改成 WARN。理由写进留档报告，技能升级版本时白名单要重新核对——行号变了，旧白名单就失效了。

**Q12：发现疑似真实 Token，我该做什么？**

顺序是：先吊销／轮换凭证 → 检查它是否进过 Git 历史或日志 → 再下架技能包 → 最后才谈修文档。删掉文件不等于没泄露过。报告里也不要把完整值贴出来，只给文件名、行号和脱敏片段。

**Q13：规则能自己加吗？**

能。在 `scripts/audit.py` 的 `RULES` 区用 `rule()` 注册，再在 `selftest.py` 补一组样本，最后同步 `references/规则清单.md`。只有「正常文档里绝无正当用途」的特征才设 BLOCK，其余一律 WARN。详见规则清单最后一节。

**Q14：为什么把它单独做成一个技能，而不是并入某个安全工具？**

因为触发时机不同。代码审计发生在写完代码之后，技能审计发生在「装之前」，而且对象主要是自然语言文本，不是代码。两者规则集、结论口径、误报处理方式都不一样，合在一起反而容易把「文档引用了危险命令」误判成代码漏洞。
