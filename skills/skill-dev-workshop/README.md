# Skill 开发上架工厂

从「一个想法」到「平台上能搜到、能装、能迭代」的七阶段流水线。

不是又一个「教你写 SKILL.md」的模板。它覆盖的是大多数人漏掉的那七成工作：**选题验证、质量闸门、上架物料、发布工程、数据复核**，并附一份真实踩坑记录。

---

## 一分钟上手

告诉 Agent 你现在在哪一步：

```
用 skill-dev-workshop，我在 P0（还没定题 / 已有想法 / 写完 SKILL.md / 已上线没人用）。
【我的想法】……
【已有材料】……
```

Agent 只给当前阶段的交付物和闸门结论，不会把七个阶段一次性倒给你。

| 你在哪 | 会得到什么 |
|---|---|
| 还没定题 | 选题卡：目标词、同义词实测、真实竞品头部、差异化、slug 查重 |
| 定完题 | 规格表：frontmatter 字段、触发条件、能力边界 |
| 正在写 | SKILL.md 七段式骨架 + references 分层建议 |
| 准备上架 | 38 项质量清单验收 + verify.py 自检 + 上架物料卡 |
| 发布中 | 打包结构、payload 核对、限流与审核状态处理 |
| 已上线 | 搜索命中核查、下载/星标基线、命名优化建议 |

## 七阶段

| 阶段 | 名称 | 闸门 |
|---|---|---|
| P0 | 选题验证 | 有一个「有搜索量 + 竞品不强 + 我能做得更好」的词，slug 未被占 |
| P1 | 规格设计 | frontmatter 字段齐、触发条件 ≥5 条、边界明确 |
| P2 | 内容生产 | 七段式齐全、三个真实示例、references ≥2 个 |
| P3 | 质量闸门 | 38 项清单 0 未通过，verify.py 0 FAIL |
| P4 | 上架物料 | 名称 = 搜索词、摘要前 80 字含 8–12 触发词、图标 96px 可辨 |
| P5 | 打包上架 | slug 查重、密钥隔离、限流、审核状态分开记录 |
| P6 | 数据复核 | 精确 slug 可搜到、基线已记录、优化项排好优先级 |

## 一个最容易犯的错

**把「发布成功」当成「已上线」。** 发布返回 201 只说明收了，返回体里内容审核、图标审核、安全扫描、review 可能全是 `pending`。正确做法是分开记录两个状态，用精确 slug 查索引，查不到就标「审核中」。

另一个同样常见的错：**用模糊搜索前几条判断竞品**。搜索接口会拿热门条目补位，看着像被百万级头部垄断，实际相关竞品可能只有几个、最高几千下载。判相关性要看名称/描述里是否真含关键词，并按作者去重。

## 配套文件

- `SKILL.md` — 七阶段完整工作流、输出模板、三个真实示例、硬规则、反模式
- `references/质量清单.md` — 38 项，分七组，逐项给检查方法与不通过后果
- `references/实战踩坑库.md` — 16 个真实故障，含现象 / 原因 / 修法 / 预防
- `scripts/verify.py` — 机器自检（文件、frontmatter、命名一致性、关键章节）

```bash
cd skill-dev-workshop && python scripts/verify.py
```

## 能力边界

- 不刷下载 / 刷星标 / 批量注册马甲占词 / 抄袭他人技能 / 编造平台数据。
- 不保证上架必过审核、搜索排名、下载量，也不保证平台接口长期不变。
- 不读取、不打印、不上传任何凭据明文；只描述密钥应该放在哪里。
- 涉及医疗、金融、法律、未成年人等敏感领域，需另做专业合规评审。

**底线：宁可少上一个技能，也不上一个自己都不愿意装给自己用的技能。**
