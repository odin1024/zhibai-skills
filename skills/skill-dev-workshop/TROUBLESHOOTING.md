# 异常处理

> 原则：把「不确定」显式写出来，不补一个看起来合理的结论。

---

## 1. 用户只有一个模糊想法，没有任何资料

**表现**：「我想做个帮人写周报的技能」。

**处理**：不直接写 SKILL.md。先跑 P0：列出 3–5 个同义说法让用户确认、说明需要实测哪些数据、给出「做完这步会得到什么」。若用户坚持先看成品，交付一版**标注为「未验证选题」的骨架**，首页写明「本版未经关键词实测与 slug 查重，不可直接上架」。

## 2. 关键词实测拿不到数据 / 接口异常

**处理**：不编造下载量。记录「接口不可用 + 时间 + 具体错误」，降级为定性判断：列出同义词、说明哪类词更可能是用户说法，并在选题卡里标【待实测】。闸门结论写「暂缓，待实测」，不要写「通过」。

## 3. 搜索结果全是热门补位噪声

**处理**：按 `slug / displayName / description` 是否含关键词筛相关条目，按 `owner_name` 去重。若相关条目为 0，写「未找到相关竞品（可能需求不存在，也可能词不对）」，建议换 2–3 个同义词重测，不要直接下「蓝海」结论。

## 4. 候选 slug 全部被占

**处理**：不硬抢、不加随机后缀凑数。回到 P0 换一个语义更独特的词根，或组合「场景 + 动作」构造新 slug；给出 3 个候选并逐个精确查重，附 `owner_name`。若同名条目全是自己账号的，说明不是冲突，按作者区分后继续。

## 5. 质量清单有未通过项，但用户要求马上上架

**处理**：可以一次给全物料，但闸门结论必须写「否」，并逐项列出未通过项与后果。事实准确性和安全合规两组的未通过项**不允许带着上架**，其余项可由用户明确接受风险后继续——要把这个决定写进验收记录，不要静默放行。

## 6. verify.py 报 FAIL，但看起来是误报

**处理**：先判断根因。常见两类：① 目录被重命名导致 slug/目录名不一致 → 修命名，不改脚本；② 规则字面量被自己的扫描器命中 → 用分段拼接并排除脚本自身。**不要为了让检查通过而放宽检查**，若某项 WARN 确实可接受（如 `references_xxx.md` 命名会映射成子目录），在验收记录里写明理由。

## 7. 发布失败：409 / 429 / 5xx

| 状态码 | 含义 | 处理 |
|---|---|---|
| 409 | slug 被他人占用 | 换 slug，重跑查重，同步改 displayName |
| 429 | 触发限流 | 停止并发，等 ≥45 秒后顺序重发；把间隔写进脚本默认值 |
| 5xx / 超时 | 平台侧或网络 | 先查是否已生成 skillId，**避免重复发布**；未生成再重试一次 |
| 401 / 403 | 凭据无效或权限不足 | 检查 Key 与 scope，不在错误凭据上反复重试 |

## 8. 发布成功但一直搜不到

**处理**：按顺序排查——① 返回体里的审核状态是否仍有 pending；② 用精确 slug 查索引，别用模糊词；③ 确认 payload 里 tags / keywords / summary 是否真的带了；④ 检查名称是否和核心搜索词一致。四项都正常仍搜不到，标「等待索引同步」，记录时间，隔一段时间复核。

## 9. 图标不合格（水印 / 糊 / 和名字无关）

**处理**：不用「先凑合发，以后再换」。重新生成手绘矢量，输出 96px 预览确认可辨，再走 P4 验收。图标会影响点击率，返工成本远低于带着坏图标上线。

## 10. 用户要「帮我刷初始下载 / 多开几个号占词」

**处理**：明确拒绝并说明原因（平台规则、账号信誉、数据复核失去意义）。可以给的替代方案是：名称与摘要优化、站外导流物料、7 天数据复测计划。

## 11. 批量发布中途失败，不知道哪些成功了

**处理**：停止继续发。用精确 slug 逐个查索引与 skillId，列「已发 / 未发 / 状态不明」三张表；只补发「未发」的，状态不明的先查再决定，**绝不盲重发**。之后给发布脚本加逐项结果与总数核对。

## 12. 用户问「多久能到 1 万下载 / 能不能排第一」

**处理**：不预测、不承诺。可以回答的是可核对的事实：当前下载基线、名称与目标词的匹配度、相关竞品头部、待补物料项数。

## 自检脚本异常

```bash
cd skill-dev-workshop && python scripts/verify.py
```

| 输出 | 含义 | 处理 |
|---|---|---|
| `缺少必需文件` | 技能包被裁剪 | 补齐 5 个必需文件 |
| `slug 与目录名不一致` | 目录被改名 | 让目录名、`_meta.json`、SKILL.md 的 slug 一致 |
| `SKILL.md 缺少关键章节` | 编辑时删了章节 | 按七段式补回 |
| `缺少深度参考库` | references 文件被移动 | 放回 `质量清单.md` 与 `实战踩坑库.md` |
| `references_*.md 用了下划线命名` | 提示项，非错误 | 打包时映射成 `references/`，在验收记录里写明即可 |
