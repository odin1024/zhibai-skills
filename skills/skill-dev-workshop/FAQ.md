# 常见问题

## 1. 我已经会写 SKILL.md 了，还需要这个吗？

看你在哪一步卡住。如果技能写完就有人用、能被搜到、有稳定下载，那确实不需要。如果卡在「没人搜到」「没下载」「不知道还缺什么」「发布老失败」，那 P0、P3、P5、P6 才是重点，写文档只占其中一小段。

## 2. 为什么说选题比写文档重要？

名字就是搜索词。实测过同一需求的不同说法，头部下载能差一千倍以上；一个加了「AI 时代」前缀的名字，核心词被稀释，下载只有同赛道头部的万分之一。名字错了，后面两万字都很难被看见。

## 3. 怎么判断一个词的真实竞争度？

别看模糊搜索前几条。搜索接口会补位，把几百万下载的热门条目塞进来。正确做法：筛出 `slug / displayName / description` 里真含关键词的条目，按 `owner_name` 去重，再看这些相关条目的下载分布。核查是否被收录时，用全量分页 + `fullName` 精确匹配最稳。

## 4. slug 查重显示「已占用」，是不是就没法做了？

不一定。先按 `owner_name` 看是不是自己已上线的技能——自己占用的不算冲突。确实是别人的，就换一个语义独特、不易撞车的 slug，别去抢热词。另外有些同名条目是外部导入的，同样会占索引位置。

## 5. 发布返回 201，为什么站内搜不到？

返回体里通常有多个 `pending`：内容审核、图标审核、安全扫描、review。索引要等审核后才进。把「发布成功」和「已可见」分开记录，用精确 slug 查索引，查不到就标「审核中」，别急着改内容重发。

## 6. 批量发布为什么这么慢？

同一账号两次发布通常要间隔 45 秒以上，硬并发会触发 429，反而更慢。顺序执行、默认留 50 秒，是实测下来的稳做法。

## 7. 图标能用 AI 生成吗？

能，但生成图常带右下角水印，缩略图里很显眼。更稳的是代码手绘矢量：渐变底 + 白色大色块 + 一个和名字相关的符号 + 底部暗角，然后缩到 96px 看一眼还认不认得出。图标是用户第一眼看到的东西，别用占位图。

## 8. 38 项清单太多了，能不能只跑机器自检？

`scripts/verify.py` 只能查文件、字段、命名、章节是否齐全，查不出「示例是不是编的」「路径是不是过时的」「摘要里有没有触发词」。时间紧就优先跑第 1–6 项（事实准确性）和第 31–35 项（搜索分发），这两组最直接影响用户和分发。

## 9. 上线一周 0 下载，是不是选题失败了？

先别下结论。按下载排序的搜索里，新技能天然排不上，这是冷启动死锁。可控动作是：对齐精确搜索词改名称与摘要、把物料做扎实、从站外导流。记录基线，7 天后复测。**多发几个同质技能冲量只会稀释账号**。

## 10. 能不能帮我刷点初始下载 / 多注册几个马甲占词？

不做。平台规则与长期账号信誉都比短期数字重要，这类操作也会让数据复核失去意义。

## 11. 包内目录结构有什么硬性要求？

根级放 SKILL.md、README.md、FAQ.md、TROUBLESHOOTING.md、_meta.json；`scripts/`、`references/` 保持子目录。两个高频错误：打包时把 `scripts/verify.py` 平铺到根目录；本地用 `references_xxx.md` 命名却没映射成 `references/xxx.md`。打包后列一次包内清单逐项比对。

## 12. 中文文件名有什么要注意？

走 HTTP API 推送时路径必须 percent-encode，否则会静默丢文件。批量脚本要输出逐项结果并核对总数，别只看「命令没报错」。

## 13. 密钥怎么放？

放环境变量或项目里的 `.env`，写进 `.gitignore`，发布前扫一遍包内文件清单。技能包里不应该出现任何凭据明文，技能本身也只描述「应该放哪里」，不读取、不打印、不上传。

## 14. 这个技能适用于带后端、要登录、要调模型的应用吗？

P0–P3（选题、规格、内容、质量）适用；但数据持久化、鉴权、密钥、用户数据合规需要另做专门设计与评审，不在本技能范围内。

## 15. 平台接口变了怎么办？

以当前实测返回为准。`references/实战踩坑库.md` 里的修法不是通用结论，遇到新行为按「现象 → 原因 → 修法 → 预防」追加记录，并同步更新质量清单里相关检查项。
