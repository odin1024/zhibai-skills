# 异常处理

> 原则：信息不足就追问一个具体事实，**绝不替用户补一段经历或一个数字**。

---

## 1. 只有「陪我练面试」，没给岗位和经历

**处理**：不直接开问。先要三样最小信息：目标岗位（+JD 要点，三行也行）、想练的题型、一段真实经历。若用户坚持马上开始，用「通用行为链」问一个不涉及具体岗位的问题，并在建档卡里标【岗位信息待补，岗位关联维度暂不评分】。

## 2. 用户的回答全是形容词

**表现**：「我积极推动，效果不错，收获很大」。

**处理**：不往下追新方向，先追「能给我一个具体例子吗 / 这一步具体是你做的还是别人做的」。连续两轮仍无具体事实，换更基础的链，并在复盘里记为「事实密度不足，建议先回简历把动作写具体」。**不要替他把话补圆**。

## 3. 用户要求「帮我编一段经历 / 编个数字」

**处理**：明确拒绝并说明原因（会被追问穿、背调风险）。给替代方案：从真实经历里找一件更小但讲得清的事，或用「没有数据怎么办」的三种说法，并列出面试前要核对什么。

## 4. 用户把团队成果说成独立完成

**处理**：不直接指责。第 3 问追「这件事一共几方参与、你负责哪一段」，评分里在可信度维度标注证据，改写时给「把『我们』改成『我』」的安全说法。若用户坚持不改变口径，如实记录风险，不替他美化。

## 5. 用户答不上来 / 明显情绪受挫

**处理**：给一个提示角度（例如「可以先只说当时你做的第一个动作」），不替答、不降低评分标准。连续两轮答不上来就换链，复盘里把「下一轮重点」收敛到 1 条，避免让人觉得被考倒了。评分只针对这一答，不评判人。

## 6. 用户一次回答里塞了好几件事，链条走乱了

**处理**：先挑其中一件最有细节的，说「我先追这一件」，把其余记为「待练」。不要试图同时追三条线，也不要把多个互不相关的问题合并到一条消息里。

## 7. 用户问「这样答能过吗 / 能拿多少分」

**处理**：不预测录用结果、不给「通过率」。可以回答的是可核对的事实：这一答四维得分、最该改的一处、和 JD 核心能力词的对应情况。

## 8. 用户打听某公司的真实面试题、面试官偏好

**处理**：说明这是通用模拟，不代表任何公司流程，不编内部信息。可以把问题抽象成通用追问点继续练（例如「如果对方问到架构取舍，我们练这条链」）。

## 9. 用户要薪资建议 / 要不要接 offer

**处理**：只练表达结构（预期怎么算、还看什么、结构不同怎么比），不报数、不代做决定。用户坚持要结论时，建议结合公开薪酬信息与个人情况自行判断。

## 10. 复盘时用户回忆不全

**处理**：把记得的部分按四维评分，不记得的标【记不清】，不补编。复盘报告里如实写「本轮基于用户回忆，可能与现场有偏差」，下一轮重点只给 1–2 条。

## 11. 用户说「停 / 换题 / 直接给结论」

**处理**：立刻停止追问，给当前已产生的复盘（哪怕只问了 1 轮）。换题就重新走 W2 选链并说明换了什么，不硬把原链走完。

## 12. 敏感领域或特殊经历（竞业、仲裁、健康、家庭）

**处理**：不追问细节、不建议隐瞒或编造。只给通用的表达原则（事实照说、不做人身评价、落到现在想要什么），并提示涉及法律或协议的事项应咨询专业人士。

## 自检脚本异常

```bash
cd interview-mock-chain && python scripts/verify.py
```

| 输出 | 含义 | 处理 |
|---|---|---|
| `缺少必需文件` | 技能包被裁剪 | 补齐 5 个必需文件 |
| `slug 与目录名不一致` | 目录被改名 | 让目录名、`_meta.json`、SKILL.md 的 slug 一致 |
| `SKILL.md 缺少关键章节` | 编辑时删了章节 | 补回工作流 / 输出规范 / 示例 / 判定规则 / 反模式 / 边界 / 自检 |
| `缺少深度参考库` | references 文件被移动 | 放回追问链库与 STAR 改写库 |
| `references_*.md 用了下划线命名` | 提示项，非错误 | 打包时映射成 `references/`，可忽略 |

---

## 使用纪律速查

- 一次只追一问，追问咬住上一答的具体内容。
- 评分四维齐全且每条有证据；改写不添加任何用户没说过的事实。
- 不冒充、不承诺、不替决策、不追问隐私。
- 用户喊停就停，并给复盘。
