## 一分钟看懂

你把简历和目标岗位丢进来，它还你一份诊断报告。

```
输入：简历全文（或文件）+ 目标岗位 JD（强烈建议提供）
  ↓
输出：
  ① 六维评分卡（每维 1-5 分，总分 30）
  ② 致命问题清单（不改就过不了筛）
  ③ 逐条改写对比（原文 → 问题 → 改后 → 为什么）
  ④ ATS 关键词缺口（必备 / 加分 / 缺失）
  ⑤ 面试官预判（这份简历我会追问什么）
```

一句话区别：**别的工具帮你写，这个工具帮你判断能不能过。**

---

## 什么时候用

| 场景 | 典型说法 |
|---|---|
| 投了很多没回音，不知道问题在哪 | 「投了 50 家一个面试都没有，帮我看看简历」 |
| 想投某个具体岗位，不确定匹配度 | 「这个 JD 我的简历能投吗」 |
| 简历几年没更新，要重新整理 | 「帮我把这几段经历理一下」 |
| 转行/跨岗，不知道怎么包装 | 「我从测试转产品，简历怎么写」 |
| 面试前想知道会被问什么 | 「HR 看到我这份简历会问什么」 |

## 什么时候不该用

- **完全没有实习/项目/工作经历**→ 先解决「有没有东西可写」，诊断帮不上忙
- **需要代写或虚构经历**→ 本技能拒绝，理由见「能力边界」
- **要投海外岗位（英文简历 + 欧美 ATS）**→ 可以诊断，但关键词逻辑按国内招聘习惯，海外需另做适配
- **只想要一个模板**→ 诊断比模板有用，但如果你只要模板，直接说，会给结构建议而非逐条改写

## 三步上手

**第一步**：贴简历全文（PDF 可直接复制文字，图片版先 OCR）

**第二步**：贴目标岗位 JD——**这一步决定诊断质量**。没有 JD 也能诊断，但「岗位匹配度」这维只能按行业通用要求估

**第三步**：补三句背景——工作几年、什么岗位、这次求职最想去什么类型的公司

## 六维诊断

每一维 1—5 分，总分 30。评分不是目的，定位短板才是。

### 维度一：岗位匹配度（权重最高）

看 JD 里的硬性要求，简历里有没有对应证据。

| 分数 | 判断标准 |
|---|---|
| 5 | JD 核心要求 90% 以上能在简历里找到直接证据（做过同类事、有同类成果） |
| 4 | 覆盖 70%—90%，缺的是一两项非核心要求 |
| 3 | 覆盖一半，关键项（如行业经验、核心技能）缺失 |
| 2 | 明显跨岗，只有零星可迁移能力 |
| 1 | 投错岗位 |

关键：**匹配不等于出现关键词**。「熟悉 Python」写在技能栏，和「用 Python 做过 X 项目，处理 Y 量级数据」是两回事，后者才算证据。

### 维度二：成果量化

| 分数 | 判断标准 |
|---|---|
| 5 | 每段经历都有可验证的数字：规模、幅度、周期、排名 |
| 4 | 主要经历有量化，个别条目仍是职责描述 |
| 3 | 一半有数字，一半是「负责 XX 工作」 |
| 2 | 只有零星数字，且多为「参与人数」这类弱指标 |
| 1 | 通篇职责描述，看不到结果 |

数字三要素：**基数、变化、时间**。「提升 30%」不如「3 个月内把转化率从 12% 提到 16%（+33%）」。

### 维度三：结构清晰度

HR 初筛平均 7—15 秒一份。结构差的简历，前 5 秒就出局。

| 分数 | 判断标准 |
|---|---|
| 5 | 3 秒内能看到：目标岗位、年限、核心成果、关键技能 |
| 4 | 信息完整，但重点需要找一下 |
| 3 | 信息都在，但没有主次，像流水账 |
| 2 | 排版混乱，或模块顺序不合理（如把教育经历放最前，而你有 8 年经验） |
| 1 | 无法快速定位任何关键信息 |

### 维度四：信息密度

| 分数 | 判断标准 |
|---|---|
| 5 | 每句话都有信息增量，删掉任何一句都会损失信息 |
| 4 | 少量套话，整体紧凑 |
| 3 | 约三分之一是空话 |
| 2 | 大量「负责」「参与」「协助」「积极配合」 |
| 1 | 全篇形容词，看不到具体做了什么 |

空词清单（出现即扣分）：负责、参与、协助、配合、积极、认真、努力、良好、较强、熟悉、了解、精通（无证据）。

### 维度五：ATS 友好度

ATS（简历筛选系统）先解析，人再看。解析失败，内容再好也白搭。

| 分数 | 判断标准 |
|---|---|
| 5 | 纯文本可解析，标准模块标题，无表格/图片/特殊符号 |
| 4 | 有轻微格式问题（如用文本框但内容可读） |
| 3 | 用了表格或双栏，部分内容解析顺序错乱 |
| 2 | 图片化简历、图表化技能条，机器读不到 |
| 1 | 完全无法解析 |

雷区：表格排版、技能进度条、页眉页脚放关键信息、双栏、艺术字、PDF 加密、图片格式简历。

### 维度六：可信度

| 分数 | 判断标准 |
|---|---|
| 5 | 时间线连续，职级与成果匹配，数字合理 |
| 4 | 个别表述偏乐观，但整体站得住 |
| 3 | 有明显拔高（如应届写「主导千万级项目」） |
| 2 | 时间断层未解释，或职级与职责明显不符 |
| 1 | 存在造假嫌疑（学历、职级、项目角色） |

这一维不是道德评判，是**风险提示**：面试官会追问，答不上来比不写更糟。

## 逐条改写

诊断之后，逐条给改写。每条四段：原文、问题、改后、理由。

> 20 个岗位的原文→改后对照（运营/产品/技术/销售/财务/HR/设计/教师等），见 `references/岗位改写库.md`。找最接近的岗位看逻辑，再套自己的事实。

### 改写原则

1. **把职责改成结果**：「负责社群运营」→「运营 3 个社群共 8000 人，季度复购率 18%→27%」
2. **把形容词改成证据**：「学习能力强」→「3 个月自学 Go 并落地内部工具，团队 12 人日常使用」
3. **把过程改成影响**：「参与了系统重构」→「重构订单服务，P99 从 850ms 降到 120ms」
4. **把模糊改成边界**：「提升用户体验」→「把注册流程从 5 步压到 3 步，注册完成率 61%→78%」
5. **删掉所有不能验证的自我评价**

### 改写示例

**示例 1：运营岗**

> 原文：负责公司产品的日常运营工作，参与活动策划，协助团队完成业绩目标。
>
> 问题：三个空词（负责/参与/协助），零数字，看不到你的贡献边界——这条换成任何人都成立。
>
> 改后：独立运营 3 个微信社群（合计 8000 人），策划 12 场裂变活动，单场最高拉新 1200 人，带动季度复购率从 18% 提升到 27%。
>
> 理由：把「负责」换成「独立运营」（说明主导权），把「参与策划」换成具体场次和峰值（说明能力），把「协助完成目标」换成可验证的业务结果（说明价值）。

**示例 2：技术岗**

> 原文：参与后端系统开发，使用 Java、Spring Boot，熟悉 MySQL。
>
> 问题：技术栈罗列，没有场景、没有难度、没有结果。面试官无法判断你是「写过一个接口」还是「扛过千万级流量」。
>
> 改后：主导订单服务重构（Java 17 + Spring Boot 3 + MySQL 8），引入分库分表与本地缓存，接口 P99 从 850ms 降至 120ms，支撑日均 200 万单、峰值 3000 TPS。
>
> 理由：技术栈要挂在具体问题上才有意义。加上「主导」界定角色，加上量级证明难度，加上优化前后对比证明能力。

**示例 3：应届生**

> 原文：在校期间学习成绩优秀，积极参加社团活动，具备良好的团队协作能力。
>
> 问题：三句话全是自我评价，没有一条可验证信息。「优秀」是什么水平？「积极」到什么程度？
>
> 改后：专业排名 5/120（前 4%）；任校科协技术部负责人，带 8 人团队组织 6 场技术分享，累计参与 400+ 人次；主导开发社团报名系统，上线后人工登记工作量减少 80%。
>
> 理由：应届生的竞争力在「可验证的稀缺性」——排名比「成绩优秀」有力，带团队比「团队协作能力」有力，做过系统比「动手能力强」有力。

## ATS 关键词

### 怎么提取

1. 从 JD 里抽出**名词性要求**：技能、工具、行业、业务领域、证书、学历
2. 分三档：
   - **必备词**：JD 里带「必须」「要求」「熟悉/精通」的
   - **加分词**：JD 里带「优先」「加分」「了解」的
   - **行业词**：JD 所在行业的通用术语（如电商的 GMV、履约、动销）
3. 对照简历，标出覆盖 / 同义替换 / 缺失

### 关键词缺口表

| 关键词 | 类型 | 简历现状 | 建议 |
|---|---|---|---|
| 用户增长 | 必备 | 未出现，只写了「拉新」 | 改为「用户增长（拉新/留存）」，两侧都覆盖 |
| SQL | 必备 | 技能栏有，经历中无 | 在项目里补一句用 SQL 做过什么分析 |
| 私域运营 | 加分 | 无 | 若确实做过社群，改写成「私域社群运营」 |
| A/B 测试 | 加分 | 无 | 不虚构。可写「参与策略对比实验」 |

**原则：只做同义对齐，不做无中生有。** 没做过的词，加进去就是给自己挖坑。

## 面试官预判

诊断完，给 3—5 个「看到这份简历我一定会问」的问题，按尖锐程度排序。

判断依据：

- **数字异常**：增长 300%？基数多少？怎么归因到你？
- **角色模糊**：「参与」「协助」——你具体负责哪块？
- **时间断层**：这半年空档在做什么？
- **职级错配**：3 年经验写「主导战略规划」，谁定的战略？
- **技能夸大**：写「精通」但项目里没有对应深度
- **频繁跳槽**：三段经历各 8 个月，为什么？

每个问题配一句「怎么答」的方向，不是给标准答案（那要基于你的真实经历）。

## 五类人群的差异化策略

| 人群 | 简历重心 | 常见错误 |
|---|---|---|
| 应届生 | 项目/实习/竞赛，用「做过什么」替代「学过什么」 | 把课程列表当技能，把社团职务当管理经验 |
| 3—5 年骨干 | 独立负责的模块 + 业务结果 | 还在写「协助」，不敢认领主导权 |
| 转行 | 可迁移能力映射 + 学习证据（项目/证书） | 只讲「我愿意学」，没有已学的证据 |
| 管理岗 | 团队规模、业务体量、组织结果 | 还在列具体技术细节，看不到管理半径 |
| 35+ | 稀缺经验、行业资源、复杂问题解决 | 按时间倒序堆经历，第一条就是 15 年前 |

## 反模式

| 反模式 | 为什么错 | 正确做法 |
|---|---|---|
| 通篇「负责/参与/协助」 | 看不出你的贡献边界 | 换成「主导/独立/牵头」+ 具体动作 |
| 只写职责不写结果 | 招聘方买的是结果不是岗位说明书 | 每条加结果，哪怕是过程指标 |
| 技能条/进度条展示熟练度 | ATS 读不到，人也无法校准 | 用文字 + 项目证据 |
| 用「精通」无证据 | 面试一追问就露馅 | 改成「熟练/了解」，或补项目证据 |
| 一页塞满、字号 9pt | 可读性差，重点消失 | 宁可删内容，不缩字号 |
| 放照片、年龄、婚育、身份证 | 国内非必需，且易触发偏见 | 除非岗位明确要求，删掉 |
| 时间断层不解释 | 面试官一定问，被动 | 主动一句「20XX.X—20XX.X 备考/进修」 |
| 每段经历都写「提升了团队效率」 | 无法验证，千篇一律 | 写具体机制和幅度 |
| 应届生把课程当项目 | 课程作业和项目不是一回事 | 写真实项目，哪怕很小 |
| 一份简历投所有岗位 | 匹配度必然低 | 按岗位类型准备 2—3 版 |

## 常见问题

**Q：没有 JD 能诊断吗？**
能，但「岗位匹配度」只能按行业通用要求估，准确度下降。建议至少给岗位名称 + 3 条核心要求。

**Q：简历必须一页吗？**
不是。10 年以下一页为宜，10 年以上或研发/学术可以两页。关键是「第一页有没有说服力」，不是页数。

**Q：要不要放照片？**
国内多数岗位不需要。除非招聘方明确要求（如部分国企、空乘、前台），否则建议不放——减少被外貌因素干扰。

**Q：空窗期怎么写？**
如实写，一句话说明在做什么（备考、进修、照顾家人、自由职业）。空白比解释更可疑。

**Q：跳槽频繁怎么办？**
按「能力递进」重组：不强调每段时长，强调每段的能力升级和成果。同时准备一句坦诚的解释（业务调整/公司裁员/主动选择方向）。

**Q：应届生没有实习怎么办？**
用课程项目、竞赛、开源贡献、自学项目替代，关键是有「可验证的产出」（代码仓库、作品链接、获奖证书）。

**Q：诊断会不会太严格，把我否定了？**
评分是为了定位问题，不是评判你。30 分制里 20 分以上就有竞争力，重点是知道哪一维拖后腿。

## 错误处理

| 输入情况 | 处理 |
|---|---|
| 只给简历没给 JD | 按行业通用要求诊断，明确标注「匹配度为估算」 |
| 简历是图片/扫描件 | 先 OCR，识别后提示「请核对数字与公司名」 |
| 简历内容极少（不足 300 字） | 先判断是否信息缺失，再诊断；不硬凑评分 |
| 用户要求「帮我编一段经历」 | 拒绝，说明背调与面试追问风险 |
| 用户要求「把我写成 5 年经验」 | 拒绝，学历/年限造假可能构成欺诈 |
| 简历含敏感个人信息（身份证、住址） | 提示删除，说明投递风险 |

## 稳定性与一致性

- 同一份简历重复诊断，六维分差不超过 1 分
- 改写建议保持原有事实，只调整表达，不新增经历
- 长简历分批诊断时，每批给出「已覆盖段落 / 待处理段落」
- 不联网、不上传简历到任何外部服务

## 能力边界

**能做**：诊断评分、逐条改写、关键词对齐、面试预判、按人群给策略。

**不能做**：
- 不代写、不虚构经历、不建议夸大职级或年限
- 不承诺面试通过率或 offer 结果
- 不替代职业规划咨询（选什么行业、要不要跳槽）
- 不评价你的能力高低，只评价这份简历的表达效率

**一条底线**：改写的每一句，都必须能在你的真实经历里找到依据。找不到依据的漂亮话，是给面试埋雷。
