# 异常处理

## 输入类问题

| 现象 | 处理 |
|---|---|
| 只给简历，没给 JD | 按行业通用要求诊断，报告首行标注「匹配度为估算」 |
| 简历是图片或扫描件 | 先 OCR，再提示「请核对公司名、时间、数字」 |
| 简历内容过少（不足 300 字） | 先判断是信息缺失还是经历确实少。缺失就追问；确实少就按现有内容诊断，不硬凑评分 |
| 简历含大段自我评价 | 单独列出「空话清单」，逐句给删除或替换建议 |
| 简历格式混乱（表格/双栏/文本框） | 先提示 ATS 风险，再按内容顺序重建结构 |
| 简历里有多段不相关经历 | 按「与目标岗位相关性」排序建议，不直接删（可能涉及年限连续性） |

## 诊断类问题

| 现象 | 处理 |
|---|---|
| 无法判断职级 | 按「带团队规模 + 决策范围 + 汇报对象」三项推断，标注「推断值」 |
| 数字明显异常（如应届生写千万级 GMV） | 不直接否定，列入「可信度」扣分并进面试预判清单 |
| 时间线有断层 | 标注断层区间，建议补一句说明 |
| 多段经历时间重叠 | 提示核实，可能是兼职/项目制，也可能是笔误 |
| 技能与经历不匹配（技能栏写 Python，经历中无） | 标为「关键词孤立」，建议补项目证据或下调熟练度 |

## 输出类问题

| 现象 | 处理 |
|---|---|
| 改写条目太多，用户不知从哪下手 | 按「致命 → 重要 → 优化」三级排序，先给前三条 |
| 改写后字数暴涨 | 控制在原文 1.5 倍以内，超了就删次要信息 |
| 用户只要评分不要建议 | 给评分卡 + 三句话结论，不展开 |
| 用户要求保留原风格 | 只做去空词、补量化，不改句式 |
| 简历过长（超过 3 页） | 建议按「相关性」删减，给具体删除清单 |

## 流程类问题

| 现象 | 处理 |
|---|---|
| 改完一版想再改 | 贴回新版，只对比上一版做增量诊断，不重复全量评分 |
| 换了目标岗位 | 只重跑「匹配度」和「关键词缺口」两节，其余保留 |
| 投递后收到面试，想准备 | 转「面试官预判」模块，按岗位展开追问链 |
| 多份简历要对比 | 同一套六维分别打分，给横向对比表 |

## 拒绝执行

1. **要求虚构工作经历、项目、职级**——背调必露，且可能构成欺诈
2. **要求修改学历、年限、证书**——同上
3. **要求写「保证通过面试」的承诺**——无法保证
4. **要求针对某家公司做「内部信息」推测**——不提供非公开信息
5. **要求生成带歧视性内容的简历**（如刻意标注婚育、地域）——不协助
